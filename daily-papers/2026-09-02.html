🔪 今日锐评

今天是 rubric-RL 大爆发的一天——五篇论文（ARISE-RL、PaperGym、CARE、InternReviewer、外加半个 AnySearch）都在解同一个问题：开放式任务没有 verifiable gold answer，怎么给 agent 发奖励。答案高度趋同：用 rubric 当 critic + 想办法防 reward hacking。真正的硬货是两篇 scaling law（超参 scaling 和 MoE looped transformer）和一篇罕见诚实的 outcome-only RL 论文。多智能体框架照例灌了一堆，但 ChatDev 2.0 和 EDGE 值得瞄一眼。

1. Explore More, Drift Less: Outcome-Only Reinforcement Learning Can Suffice for Long-Horizon Interactive Agents

  • 作者: Liming Pu, Xiaoxia Li, Yifu Liu, Teng Cao, Bin Yang
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 针对长程交互式 agent（AppWorld、SWE 类任务），只用 end-of-task 的 outcome-only reward 做 RL post-training，不加 dense reward、不加 SFT prior、不搭 skill library / memory / 多智能体编排。核心论点是：小开源模型在 outcome-only RL 下并没有大家以为的能力天花板，关键在于探索得够多（Explore More）、策略漂移得够少（Drift Less）。

  • 对比方法/Baselines: 对比一整排 dense reward、SFT 冷启、skill library、curated memory、multi-agent orchestration 等"补偿式"方法。
  • 借鉴意义: 对做广告/推荐 agent 或任何长程决策 RL 的人，这是一篇能省钱的论文——它在说你精心设计的 reward shaping 可能是过度工程。
  • 锐评: 标题就是暴论，而且是我今天最喜欢的那种暴论。整个领域都在往 RL 训练外面堆脚手架，这篇直接说"你们堆的东西可能没用，outcome-only 就够"。如果实验扎实（AppWorld 这种 canonical benchmark 上验证），杀伤力很大。唯一要警惕的是"suffice"这个词有多少水分——摘要里"small open models"的边界在哪、多小算小，得进正文核。但敢和主流对着干且给了 benchmark，值得精读。🔥

  • 作者: Fanrui Zhang, Ruixue Ding, Qiang Zhang, Xi Chen, Boli Chen, Shihang Wang, Hongmin Zhan, Jinxin Bian, Xingchao Li, Peijin Zheng, Hao Cheng, Pengjun XieKaipeng Zhang, Jiawei Liu, Zheng-Jun Zha

  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: ARISE-RL 针对开放式 agent 任务缺 verifiable gold answer 的问题，做 rubric-grounded 的迭代式自进化（self-evolution）+ RL。用可扩展 rubric 当奖励基准，并处理长程开放任务里 reward 脆弱、rollout 对比信号弱（group-based policy learning 拿不到细粒度优化信号）的问题。

  • 借鉴意义: 开放式 agent 的奖励设计是当前 RL 落地最大的卡点，rubric-as-critic 是主流解法之一。
  • 锐评: 今天 rubric-RL 五连发里分最高的一篇（score 7），Alibaba 出品。方向没错，痛点抓得准——长程开放任务 reward 又脆又噪确实是真问题。但"self-evolution + rubric + iterative"这套组合词今天出现太多次了，得看它相比 CARE、PaperGym 到底新在哪，别是换皮。摘要没给硬数字，significance 待正文验证。方向对，先收藏。👀

3. One Policy, Any Budget: Internalizing Budget-Aware Search via Reinforcement Learning

  • 作者: Xiaowei Sun, Jin Li, Yili Hong, Yikun Fu, Yanghua Xiao
  • 机构: Email: shawyh@fudan.edu.cn, Email: fuyikun123456@sjtu.edu.cn, Email: xwsun24@m.fudan.edu.cn, Affiliation: College of Computer Science and Artificial Intelligence, Fudan University, Affiliation: School of Artificial Intelligence, Shanghai Jiao Tong University, Affiliation: , Email: ylhong24@m.fudan.edu.cn, Email: , Affiliation: College of Software Engineering, Southeast University
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: AnySearch 让单一策略在任意 budget 约束下做 budget-aware search。现有 RL 搜索 agent 训练时 budget 固定，部署时约束一变就失效。AnySearch 用一个训练脚手架 + 课程式 RL（curriculum RL），把"预算感知"内化进策略，无需推理时显式给 budget 信号。
  • 对比方法/Baselines: 对比 StepSearch、ZeroSearch、以及 BRPO、OTC-PO、IKEA 等需要显式 budget 信号的方法，在 HotpotQA 等上评测，用 GRPO 训练。
  • 借鉴意义: 部署场景 budget 天天变（成本预算、延迟预算），一个策略吃所有预算比训 N 个策略实用得多。
  • 锐评: "One Policy, Any Budget"是个漂亮的产品化诉求——线上流量高峰砍预算、低峰放开，不可能给每档预算训一个模型。把 budget 内化到策略里、推理时不用显式传信号，这个设计对工程友好。curriculum RL 做 budget 泛化也是合理路径。就是"any budget"的外推边界在哪（训练见过的预算范围外还灵不灵）得核实。做搜索/工具调用 agent 且在乎成本的值得看。👀

4. CARE: Contrastive Anchor-based Rubric Evolution for Large Language Model Post-Training

  • 作者: Siyuan Li, Xinxin Song, Chen Ruinian, Jingjing Fan, Tingxiong Xiao, Yangen Hu, Ke Zeng, Jinli Suo
  • 机构: Affiliation: , Affiliation: jlsuo@tsinghua.edu.cn, Affiliation: Department of Automation, Tsinghua University
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: CARE（Contrastive Anchor-based Rubric Evolution）做 rubric-based RL 的 post-training。指出静态 rubric 随策略进化必被 hack，而现有动态 rubric 方法有三个新病：无方向的 rubric 抽取、不可靠的 hack 检测、rubric 无限膨胀。CARE 用对比锚点来演化 rubric 并抑制这三个问题。
  • 对比方法/Baselines: 对比 Bradley-Terry RM、静态 rubric、以及其它动态 rubric 方法，在 InfoBench、FollowBench、Arena-Hard 上评测。
  • 借鉴意义: reward hacking 是 RL post-training 的顽疾，把 rubric 演化做得可控（不膨胀、能检测 hack）是实用改进。
  • 锐评: 把动态 rubric 的三个病列得很清楚（无方向抽取、hack 检测不靠谱、rubric 膨胀），这种"先诊断再开药"的写法我喜欢。对比锚点防 hack 是合理机制。但今天光 rubric-RL 就五篇，CARE 和 ARISE-RL、PaperGym 的边界在哪必须看清——都在说自己解决了 reward hacking，到底谁的实验更硬。清华出品，先归到值得看。👀

  • 核心方法: PaperGym 做 research-plan generation 的 rubric-centered evolution。核心问题：研究计划没有 verifiable answer，RL 缺 critic。用从论文抽的 rubric 当 critic，但指出现有 pipeline 从同一段内容同时抽 question 和 criteria，导致 reward 可以靠 paraphrase 骗到。PaperGym 用 GRPO + rubric 演化解决这个泄漏问题。

8. Efficiently Estimating Optimal Hyperparameter Scaling Laws through Power-Law Entropy Search

  • 作者: Zhiliang Chen, Sebastian Ament, David Eriksson, Maximilian Balandat, Eytan Bakshy, Jihao Andreas Lin

  • 机构: National University of Singapore , Atomic Machines; work done at Meta , National University of Singapore, Meta

  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 提出 PLES（Power-Law Entropy Search）来高效估计"最优超参 scaling law"——即最优超参如何随模型/数据规模变化。传统做法要在上千次训练上做穷举 grid search，本文用 Power-Law 先验 + Bayesian Optimization（GP 代理模型 + 熵搜索采集函数）把这个 fit 出来，避免生产规模上的昂贵调参。
  • 对比方法/Baselines: 对比常规 grid search、McCandlish 等 critical batch size 工作、以及标准 BO（GP + 常见 acquisition）。
  • 借鉴意义: 谁在训大模型谁受益。超参 scaling law 是"小规模调好、大规模直接外推"的关键，能省下天文数字的算力。
  • 锐评: 这是那种没什么噱头但真有人用的工程论文。把 BO 的熵搜索接到 power-law 结构先验上是自然且合理的组合——已知函数形式就该利用它，别拿 vanilla GP 硬拟。Meta + NUS 的作者阵容也靠谱。风险点：power-law 假设在哪些超参上成立、外推到真实生产规模的误差 bar 有多大，这决定它是 useful 还是 dangerous。但对做大规模训练的团队，这类论文的 ROI 远高于又一个 agent 框架。🔥

9. SMELT: Scaling Laws for Compute-Matched MoE Looped Transformers

  • 作者: Wang, Shaowen, Zhang, Ge, Luo, Kairong, Wu, Yuhao, Liu, Shaofan, Liu, Jiaheng, Huang, Wenhao, Yan, Shen, Li, Jian
  • 机构: ByteDance Seed, Tsinghua University
  • 链接: arXiv | PDF

  • 来源: 📰 HF Daily，⬆️ 52

  • 核心方法: SMELT 研究 MoE 上的 looped transformer（共享一块 layer 反复迭代来增加有效深度）的 scaling law。关键贡献是评测方法论：严格对齐 per-token FLOPs、非 embedding 总参数量、KV cache 三项后再比 loop vs 非 loop，把"架构优势"和"多花 FLOPs"这两个长期被混为一谈的因素拆开。

  • 对比方法/Baselines: 固定 model size 下比较的既有 looped transformer 评测（本文指出这类比较偷偷多用了 FLOPs）。
  • 借鉴意义: 对架构研究是一记正本清源。很多"新架构更强"的结论其实是算力没对齐，这篇给了 compute-matched 的干净比较协议。
  • 锐评: ByteDance Seed + 清华，方法论意识在线。"conflating architectural advantage with extra FLOPs"这句吐槽精准命中了半个架构圈的通病——太多论文赢在偷偷加算力。把 FLOPs/参数/KV 三个维度全 match 死再比，这才是该有的姿势。就冲这个 fair-comparison 的态度就该给赞。想看 loop 到底是不是免费午餐的，直接读结论表。🔥

10. EDGE: Error Dependency Graph-Guided Multi-Error Attribution in Multi-Agent LLM Systems

  • 作者: Jun Hou, Priya Pitre, Yi Fang, Xuan Wang
  • 机构: Affiliation: 
  • 链接: arXiv | PDF

  • 核心方法: EDGE（Error Dependency Graph-Guided）做多智能体 LLM 系统的多错误归因。关键洞察是 agent 失败往往是多个相关错误的链条而非单点，现有方法只找一个"责任 agent/步骤/根因"，不建模错误之间的依赖。EDGE 显式构建错误依赖图来做归因。
