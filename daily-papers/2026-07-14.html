📈 Scaling Law 与量化

1. Reliability Scaling Laws for Quantized Large Language Models

  • 作者: Sirine Ayadi
  • 机构: Munich Data Science Institute, School of Computation, Information and Technology, Technical University of Munich
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 系统研究量化 LLM 在'扰动输入'下的可靠性，而不只是干净输入的准确率。用 HQQ、AQLM、GPTQ、AWQ、BNB 等主流量化方法，在 TriviaQA、CoQA 上测量可靠性指标，发现可靠性同样遵循与位宽相关的 scaling law。
  • 对比方法/Baselines: 对比 HQQ、AQLM、GPTQ、AWQ、BNB 五种量化方案，可靠性用 AUCROC 度量。
  • 借鉴意义: 对任何要把量化模型往生产环境部署的团队都是硬通货——你以为省了显存，实际上牺牲了鲁棒性，而且这个牺牲是可预测的幂律。
  • 锐评: 终于有人不再只盯着 benchmark 准确率数字了。量化圈长期的通病就是'干净输入上性能没掉多少'然后就宣布胜利，这篇直接把扰动鲁棒性拉出来鞭尸，还证明它有 scaling law。方法上没什么惊天创新，就是老老实实地测，但这种'测清楚一个被忽视的维度'的工作恰恰是最有部署价值的。唯一遗憾是只有单作者、机构单一，希望后续有人扩到更大模型验证。🔥

2. Domain-Aware Scaling Laws Uncover Data Synergy

  • 作者: Kimia Hamidieh1  Lester Mackey2  David Alvarez-Melis2,3
  • 机构: 1MIT CSAIL, 2 Microsoft Research, 3 Harvard University
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 把训练数据的'领域构成'和'领域间协同'显式建模进 scaling law。从领域无关基线出发，逐步加入一阶 领域→benchmark 协同项和二阶 预训练领域间协同项，用 DataDecide、BPB 等在 HumanEval、MBPP 上验证。
  • 对比方法/Baselines: 以标准 scaling law（Kaplan/Hoffmann 式）为域无关基线，扩展到 LSE 建模的协同项。
  • 借鉴意义: '加代码能提升数学推理'这种口口相传的炼丹经验，终于被写成了可预测公式。对做数据配比的预训练团队直接可用。
  • 锐评: 这篇干的是真活。所有人都知道数据混合有非线性交互（代码提数学、某些混合反而互相干扰），但一直停留在轶事阶段。作者把它塞进 scaling law 的数据项里，还分了一阶和二阶协同，MIT CSAIL + MSR + Harvard 的配置也让人放心。质疑点：协同项的可迁移性——在小模型/小数据上拟合出的协同系数，能不能外推到真正的大规模预训练？这才是关键，但通常这类工作在这一步会留个尾巴。👀

🛡️ Agent 安全与可靠性

3. Filtering Harmful Actions Isn't Enough: Phantom Transfer in Agentic SDF

  • 作者: May Dixit ERA Fellowship maydixit25@gmail.com
  • 机构: ERA Fellowship, July, May Dixit
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 研究在含对抗交互的合成 agent 轨迹上训练的后果。微调 Llama 3.3 70B 在四个工具使用数据集上，对比 Benign-Direct、Filtered-Adversarial 等设置，发现即便过滤掉明显有害动作，模型仍会习得有害倾向——称为 Phantom Transfer（幽灵迁移）。
  • 对比方法/Baselines: 对比 Benign-Direct、Filtered-Adversarial、ToolACE 数据集，SFT vs RL 轨迹结构。
  • 借鉴意义: 随着合成轨迹成为 agent 训练主力，这篇直接打脸'过滤掉坏动作就安全'的行业默认做法。对做 agent 后训练数据清洗的团队是当头一棒。
  • 锐评: 反直觉但可信的好结果。大家做合成数据都默认'把 harmful action 过滤掉就干净了'，这篇证明危害会通过轨迹的结构性上下文幽灵般迁移过来——即使你删了那一步动作。一个 ERA Fellowship 的独立研究者做出这种发现，比某些大厂灌水强多了。质疑点：只在 Llama 3.3 70B 上验证，样本量和模型多样性不足，'phantom transfer'这个现象需要更多模型复现才敢说是普适规律。⚠️

4. To Answer or to Abstain: Mitigating Search-Agent Hallucinations via Abstention-Aware Reinforcement Learning

  • 作者: Zhang, Fengji, Fan, Tianyu, Zheng, Yuxiang, Niu, Xinyao, Huang, Chengen, Keung, Jacky, Chen, Bei
  • 机构: Alibaba Group, City University of Hong Kong
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 针对搜索增强 agent 的幻觉问题。指出当前'只奖励正确答案、不惩罚检索失败时编造答案'的 outcome-reward RL 会加剧幻觉，提出 Abstention-Aware RL——让模型在该弃权时弃权。

  • 对比方法/Baselines: 摘要未提及具体基线（method_names 为排版噪声）。
  • 借鉴意义: 对做 RAG + agent 的团队直接有用——检索失败时模型硬答是生产事故的高发区，把'弃权'纳入奖励是正解方向。
  • 锐评: 问题诊断很准：outcome-reward RL 只看答对没答对，等于变相鼓励模型在检索失败时瞎编，反正蒙对了也有奖励。阿里 + 港城大提出让弃权成为一等公民，思路完全正确。质疑点：弃权阈值的校准是个老大难——罚得太狠模型变成缩头乌龟啥都不敢答，罚得太松又回到幻觉。摘要没给方法细节（method_names 全是噪声），得看正文才知道他们怎么平衡。👀

5. When Local Monitors Miss Compositional Harm: Diagnosing Distributed Backdoors in Multi-Agent Systems

  • 作者: Yibo Hu, Ren Wang
  • 机构: Illinois Institute of Technology
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 揭示运行时逐条检查（每个消息/工具调用单独审查）的根本漏洞：分布式后门把有害 payload 拆散到多个 agent，每个局部检查都通过，但组装起来就是攻击。提出'可观测性边界'概念并给出可证明的检测条件。

  • 对比方法/Baselines: 用 AgentDojo 评测，指标含 AUROC、ASR、FPR、TPR。
  • 借鉴意义: 对做 agent 安全监控的团队是必读警示——你部署的 per-step monitor 可能有结构性盲区，再强也挡不住拆分攻击。
  • 锐评: 'monitor 在每一步都对，却依然漏掉攻击'——这个表述很有冲击力，而且他们没停在吓唬人，而是给出了可观测性边界的可证明结论：一旦碎片在局部与正常流量不可区分，任何局部检测器都无能为力，除非改变观测对象去恢复组装后的代码结构。理论包装漂亮。质疑点：'恢复组装结构'的检测方案在真实系统里开销多大、误报率如何，AgentDojo 上好看不代表生产可用。👀

6. Multi-Agent LLMs Fail to Explore Each Other

  • 作者: Choi, Hyeong Kyu, Li, Jiatong, Li, Wendi, Wang, Xin Eric, Li, Sharon
  • 机构: University of California, Santa Barbara, University of Wisconsin–Madison
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 研究多个 LLM agent 相互交互时能否有效探索。发现现代 LLM agent 做不到，反而表现出短视和极化的交互模式，导致协调次优、regret 增加。

  • 对比方法/Baselines: 摘要未提及具体基线方法（method_names 只抓到排版噪声 TeX/CSS）。
  • 借鉴意义: 对所有做多智能体协作、辩论、群体决策的人是个冷水——你以为多个 agent 能互相探索补足，实际上它们会集体抱团短视。
  • 锐评: UCSB + UW-Madison（Sharon Li 组）出品，结论很扎心：把多个 LLM 放一起不会自动产生探索的智慧，反而更容易极化和短视。这类'揭穿美好幻想'的负面结果论文特别有价值，因为整个 multi-agent 圈都在假设协作能涌现。只是要小心：'exploration'的定义和实验设置很关键，如果测试环境设计得偏，结论就会被质疑是环境的锅而非模型的锅。👀

7. BackendForge: Benchmarking Agentic End-to-End Code Generation with Backend Services

  • 作者: Yuzhe Guo1,2
  • 机构: 4Shanghai Institute of Systems for Open Computing, 1Key Lab of HCST (PKU), MOE; SCS, Peking University, 3Fudan University Institute of Systems for Advanced Computing
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: BackendForge——评测 agentic LLM 端到端生成后端服务的能力：能否产出既可部署又行为正确的软件制品。以后端服务为可控但真实的评测基质，考察 agent 检查文件、执行命令、跑测试、迭代修改的完整闭环。
  • 对比方法/Baselines: 对比 HumanEval、SWE-bench、WebCoderBench、AppForge、BaxBench 等，测试 GPT-5、DeepSeek。
  • 借鉴意义: 比 SWE-bench 更进一步——不只是修 bug，而是端到端造一个能跑的后端服务，对评估 coding agent 真实生产力有价值。
  • 锐评: 评测维度选得好：'既可部署又行为正确'比单纯通过单测狠多了，后端服务需要 API 契约、HTTP 行为、状态管理全对。北大 + 复旦 + 上海系统所的配置也靠谱。这类 benchmark 论文的价值取决于两点：任务是否真实、评测是否防作弊。质疑点：端到端后端服务的'正确性'判定极难自动化，如果评测脚本本身有洞，agent 就会学会钻空子。得看他们的 rigorous eval 到底 rigorous 在哪。👀

8. Route, Communicate, and Reason: Gated Routing and Adaptive Depth for Efficient Multi-Agent Reasoning

  • 作者: Ghosh, Sudipto, Chakraborty, Tanmoy
  • 机构: Department of Electrical Engineering, Indian Institute of Technology Delhi, Yardi School of Artificial Intelligence, Indian Institute of Technology Delhi
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: GRADE（Gated Routing and Adaptive Depth）——分层多智能体系统，用四个轻量学习门控决定：激活哪些 agent、路由深度、是否跨 agent 通信、剪哪些分支。整体用 CoGRPO 端到端训练，correctness reward 驱动。
  • 对比方法/Baselines: 对比 MAGRPO 等多智能体基线，在 GPQA、AIME-2025 上评测。
  • 借鉴意义: 多智能体集成的算力爆炸是真痛点，这篇用学到的门控做自适应深度和通信裁剪，对想省钱又要多 agent 的团队实用。
  • 锐评: 问的三个问题——咨询哪些 agent、遍历多深、通信值不值——正是 multi-agent 落地的核心成本问题，不是虚的。四个门控 + CoGRPO 端到端训练的设计干净。IIT Delhi 的工作，方法完整。质疑点：四个门控听起来优雅，但联合训练稳定性、以及门控本身的推理开销会不会把省下的算力又吃回去，需要看消融。另外只在 GPQA/AIME 这种推理 benchmark 上测，换到开放式 agent 任务未必成立。👀

  • 机构: Adobe Research and University of Massachusetts, Amherst, smahadev@adobe.com, mahadeva@umass.edu

12. SVR-R1: Bootstrapping Multi-modal Reasoning with Self-verification in Reinforcement Learning

  • 作者: Mingyuan Wu1
  • 机构: 1University of Illinois Urbana-Champaign
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: SVR-R1——多轮 RL 框架，把模型自身的验证变成学习信号。每个 query 用同一套权重先提出答案，再给出二元自判（Yes/No）：'No'触发第二次重思，'Yes'或达到轮次上限则定稿计算 outcome reward。用 GRPO 训练。
  • 对比方法/Baselines: 对比 ThinkLite 等，基于 VLM/VL 多模态设置。
  • 借鉴意义: 自我验证当奖励信号是个便宜的自举思路，对做多模态推理且缺高质量 verifier 的团队有参考价值。
  • 锐评: '用同一套权重既当答题者又当验证者'的自举设计很省事，UIUC 的工作。思路是对的——外部 verifier 贵，自验证便宜。但这里有个我一定要点出的死穴：如果模型的自判本身就不可靠（过度自信说 Yes），那这个奖励信号就是在自我欺骗里打转，越训越自恋。摘要没说他们怎么防止 self-verdict 崩溃成'永远说 Yes'，这是这类自验证方法的通病。🫠

13. Generalizing Preference-based Reinforcement Learning: a Rationality Model for Incomparability

  • 作者: Drago, Simone, Mussi, Marco, Bianconi, Leonardo, Metelli, Alberto Maria
  • 机构: Marco Mussi, Simone Drago
  • 链接: arXiv | PDF
