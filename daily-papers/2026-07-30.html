🔪 今日锐评

今天是不折不扣的「Agentic RL + Multi-Agent」专场——30篇里一半在把 RL 塞进 agent，另一半在质疑 multi-agent 到底有没有用。真正戳中推荐/广告核心的只有快手的 WhisperRec 一根独苗，Meta 和 JD 各出一篇实打实的 RL 工程活，其余大量是把 LLM agent 硬套到 PID/化工/兽医/无人机等犄角旮旯领域的「换皮」论文。今日金句由两篇打脸论文贡献：一篇证明五个 agent 不如调两次 API，一篇证明 latent 通信信道其实啥也没传。

1. WhisperRec: Latent Reasoning for Efficient Foundation Recommendation Models

  • 作者: Hao Jiang1 , Peiru Du1 11footnotemark:
  • 机构: panfei05, jiangpeng, luocheng10 @kuaishou.com
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 针对基于 LLM 的推荐基座模型（FRM），指出 Think-then-Answer 范式下显式 CoT 生成冗长 rationale 带来巨大推理开销、且固定模板僵化的问题。WhisperRec 改用 latent reasoning——把推理压进隐空间而非逐 token 吐出来，配合 SID 语义 ID 和 SFT，在保留推理增益的同时砍掉显式生成成本。
  • 对比方法/Baselines: 对比 Think-then-Answer 的显式 CoT 方案、OneReason、以及 ID-based 传统推荐基座。
  • 借鉴意义: 推荐场景对延迟极度敏感，显式 CoT 在线上基本不可用。latent reasoning 是把 LLM 推理能力搬进工业推荐的关键路径，快手做这个方向说明已经在啃线上落地的硬骨头。
  • 锐评: 终于有一篇正面刚推荐系统的了。痛点抓得准——线上谁陪你等模型吐几百个 token 的思维链？把推理塞进 latent space 思路对，但老问题也在这：latent reasoning 可解释性归零，出了 badcase 你连它「想了什么」都看不到。摘要没给线上 A/B 数据，工业味能不能兑现还得看正文。快手主场，值得盯。🔥

2. Reinforcement Learning for Code Optimization

  • 作者: Chambon, Pierre, Zheng, Kunhao, Decugis, Juliette, Sagot, Benoit, Synnaeve, Gabriel
  • 机构: FAIR at Meta, Inria
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 把 RL for code correctness（生成程序→跑隐藏测试→通过给奖励）扩展到 code optimization：直接把执行时间加进 reward。论文系统性揭示一旦用 timing 驱动奖励，测量噪声、reward 稀疏、GRPO 不稳定三个问题会淹没信号导致训练失败，并给出对应的稳定化处理。

  • 对比方法/Baselines: 以标准 correctness-only RL、朴素 GRPO 为对照，验证加时间奖励后的退化与修复。
  • 借鉴意义: reward 工程是所有 agentic RL 的命门。这篇把「加个执行时间到 reward 里」这件看似 trivial 的事的所有暗坑摊开讲，对任何做 RL 训练的人都是省坑指南。
  • 锐评: Meta FAIR 的活，题目朴素到像本科作业，内容却是最实在的。它没吹自己多牛，而是老老实实告诉你「你以为加个 timing reward 就行？来看看会怎么炸」——测量噪声、稀疏、GRPO 崩塌一个不落。这种「负结果 + 修复」的诚实论文比十篇 SOTA 刷榜有用。唯一遗憾是摘要没剧透修复方案强度，得翻正文。👀

3. HiFloat4 Format for End-To-End Reinforcement Learning Post-Training of Large Language Models

  • 作者: &Hei Yi Mak &Shadan Golestan &Hoang Le11footnotemark:
  • 机构: {hei.yi.mak1, pengyunke}@huawei.com, Huawei
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 提出首个端到端 FP4 RL 后训练——rollout 和 training policy 的前向反向全部 4-bit。系统性分析发现 FP4 RL 退化的主因不是训练侧量化误差，而是 rollout 激活量化：离群值撑爆动态范围。HiF4/HiFloat4 用统一低精度 pipeline 消除 train-rollout 精度失配，配合 SmoothQuant/ResQ 处理离群。
  • 对比方法/Baselines: 对比 FP8 rollout + BF16 训练的失配方案、truncated importance sampling、自适应量化噪声/裁剪等 QAT 方法，用 GRPO/DAPO 训练。
  • 借鉴意义: RL 后训练成本高企，4-bit 全链路能大幅降本。对预算敏感的 RLHF/RLVR 团队是硬核工程增益。
  • 锐评: 华为把 FP4 RL 这块硬骨头啃了，而且诊断很到位——大家都盯着训练侧量化，它指出真凶是 rollout 激活的离群值。这种「找对病因」的洞察值钱。但 4-bit 全链路的稳定性代价是啥？摘要只讲赢，没讲在哪些任务上会掉点。低精度 RL 向来是拆东墙补西墙，得看它墙补得牢不牢。👀

4. Large Language Model for Operations Research Formulation Selection in Multi-Warehouse Inventory Allocation

  • 作者: Jintao Xu\equalcontrib
  • 机构: xujintao.3014, mayingzheng.1, dongjiong.1, qiyongzhi1, zhangjianshen@jd.com
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 把异构多仓库存分配建成 instance-wise 的 OR formulation 选择问题：没有单一 MIP 建模能通吃所有需求/库存/补货规模的分布。用 solver-guided 的 LLM 框架把每个实例路由到合适的 MIP 专家，构建 4 个 OR 专家库，用 balanced SFT + margin-weighted IPO + GRPO 的渐进式后训练，专家由 MIP solver 离线评估。
  • 对比方法/Baselines: 以单一固定 MIP formulation、以及未做 solver-guided 后训练的 LLM 路由为对照。
  • 借鉴意义: LLM 做运筹建模选择是「LLM + 传统优化」结合的务实路线，对供应链/广告预算分配等真实决策场景有借鉴。
  • 锐评: JD 的活，思路务实：不硬让 LLM 解 MIP（那是找死），而是让它当「建模路由器」选专家，把求解交回 solver。这种「LLM 干它擅长的、solver 干它擅长的」分工比端到端硬刚聪明。SFT+IPO+GRPO 三段式后训练略显堆料，真正 ablation 得看每一段贡献多少。业务价值实打实。👀

5. Collaborative Weighting with Pessimistic Critic for Mitigating Overestimation in Off-Policy Reinforcement Learning

  • 作者: Gong Gao, Xiao Lai, Ziqi Xie, Guojie Chen, Xianhui Liu, Weidong Zhao

  • 机构: 2310925@tongji.edu.cn , laixiao@sues.edu.cn

  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 针对连续控制的 off-policy RL：TD 学习引入噪声目标导致非平稳优化，贪婪策略更新又放大早期估计误差。CWAC 用悲观 critic 做协同加权（collaborative weighting）缓解 Q 值过估计。

  • 借鉴意义: 过估计是 off-policy RL 老大难，悲观 critic 是常见解法之一，对做 value-based RL 稳定性的研究者有参考。

6. SkillRise: Agentic Reinforcement Learning for Cross-Task Skill Evolution

  • 作者: Zhiyuan Yao1
  • 机构: 1Zhejiang University  2National University of Singapore  3Shanghai Jiao Tong University
  • 链接: arXiv | PDF
  • 来源: 📰 HF Daily，⬆️ 13
  • 核心方法: 指出标准 agentic RL 把每个任务当独立 episode，浪费了任务间可复用的解法模式。SkillRise 让 LLM agent 在 Cross-Task 分布上演化「技能」，用 GRPO/GiGPO 训练，避免现有 skill learning 要么只反复刷单任务、要么用多阶段 pipeline 把抽取/检索/执行搅在一起的毛病。

  • 锐评: 痛点讲得漂亮：任务间明明共享解法却被当独立 episode 白白浪费。但 skill learning 这坑前人踩过无数次，关键在「技能」怎么定义、怎么不退化成过拟合特定 benchmark。WebShop + ScienceWorld 这俩老 benchmark 说服力有限，真想证明跨任务泛化，得上更 diverse 的任务分布。想法好，就看正文的技能表征扛不扛得住。👀

7. Graph Is the Verifier: Agentic Reinforcement Learning for Interprocedural Vulnerability Detection

  • 作者: Li, Yikun, Zhang, Ting, Liu, Jiakun, Jiang, Jinfeng, Yieh, Yuheng, Yang, Yixin, Leow, Wen Bin, Yin, Yide, Huo, Yintong, Ouh, Eng Lieh, Shar, Lwin Khin, Lo, David
  • 机构: Harbin Institute of Technology, China, Singapore Management University, Singapore
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 现实漏洞常跨多个函数，但多数检测器孤立分类单个函数（71.7% 漏洞函数需要函数外证据）。VulAgentRL 用 agentic RL 让模型自己去搜集跨过程证据，核心是「图当 verifier」——用代码属性图 CPG 提供可靠 reward，解决 outcome-only reward 退化成 evidence-free 预测的问题，用 GRPO 训练。
  • 对比方法/Baselines: 对比函数级孤立分类器、SFT 方案，在 PrimeVul、CWE 数据上评测。

  • 锐评: 亮点在 reward 设计——用 CPG 当 verifier 治 outcome-only reward 退化的病，这个「图给 agent 提供可验证中间信号」的思路可以外推到很多 agentic 任务。71.7% 需要跨函数证据这个数据也够扎实立论。质疑点：图当 verifier 意味着强依赖 CPG 构建质量，图不全的时候 reward 就骗人了。但方向是对的。👀

11. SARC-DQ: Runtime Data-Quality Gating for Agentic AI: Silent Evidence Defects, the Incompetence Shield, and Downstream-Only Remediation

  • 作者: Gaston Besanson Universidad Torcuato Di Tella
  • 机构: Working paper — July 30
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: agentic 系统会行动，所以检索到的证据缺陷会变成有代价的错误行动。最危险的是元数据型缺陷：过期价格、被取代的记录——payload 里格式完美，只在新鲜度/血缘/来源上露馅，agent 根本看不到也无从怀疑。SARC-DQ 做运行时数据质量门控，用 GIGO-Bench 冻结 8 类腐败 ×4 比率 ×6 缓解方案 =192 格评测。

  • 锐评: 视角刁钻——「agent 无法怀疑它看不见的数据」这句话点破了一个被忽视的攻击面：不是数据错得离谱，而是格式完美但过期/来源污染。192 格的评测矩阵设计得像模像样。担心的是这类「working paper」容易停留在 benchmark 构造，缺乏在真实 agent 系统上的规模验证。但选题的前瞻性值得记一笔。👀

12. Two Calls Beat Five Agents: Evaluating Multi-Agent Pipelines Against Self-Refinement for Local Language Models

  • 作者: Prajapati, Ashish, Mohite, Om
  • 机构: Ashish Prajapati, Independent Researcher, Mumbai, India, Om Mohite
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 在本地小模型 Qwen2.5-7B-Instruct 上评测 Parishad（5 角色结构化 multi-agent 系统），在 GSM8K(500) 和 HumanEval(164) 上对比直接 prompting 和两次调用的 Self-Refine。结论：两次 self-refinement 打平甚至超过五个 agent 的复杂流水线。
