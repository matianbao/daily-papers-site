1. From Proprietary to Open-Source: Bridging the Distribution Gap via Multi-Agent Protocol Distillation in Agentic Search

  • 作者: Junlin Liu, Jiangwang Chen, Zixin Song, Shuaiyu Zhou, Chunji Lv, Hank Wu, Kailin Jiang, Jinyang Wu, Bohan Yu, Chenxi Zhou

  • 机构: University of Science and Technology of China, Tsinghua University , University of Chinese Academy of Sciences, Beijing Institute of Technology, University of Science and Technology of China , Beijing Institute of Technology , East China Normal University, Tsinghua University, University of Chinese Academy of Sciences

  • 链接: arXiv | PDF

  • 来源: 📰 HF Daily，⬆️ 41
  • 核心方法: 针对 agentic search 里 outcome-based RL 监督过于稀疏的问题，提出用多智能体协议蒸馏（MAPD/OPSD）把专有强模型的推理-检索交错轨迹作为稠密教师信号，蒸馏进开源模型。相比只用 GRPO 的稀疏 reward，能提供步级指导。

  • 锐评: USTC+清华一票机构联手，41 个 HF upvote 不是白来的。把「专有模型当教师、多智能体协议当稠密标注」这条思路讲清楚了，比那些只会往 agent 上套 GRPO 的强。质疑点：教师用的哪个专有模型没说清，蒸馏出来的开源模型上限被教师钉死，distribution gap 真「bridge」了还是只是搬运？🔥

AgentScope 1.0

📋 基本信息

  • 作者: Dawei Gao, Zitao Li, Yuexiang Xie 等
  • 机构: Alibaba Group
  • 链接: arXiv | PDF

🎯 研究动机与问题

现有 multi-agent 框架（如 LangChain, AutoGen）在以下方面存在不足： 1. 工具集成侵入性强：需要大量修改已有代码 2. 可观测性差：大规模部署时难以监控和调试 3. 长期记忆缺失：agent 无法保持跨会话的上下文 4. 分布式支持弱：难以扩展到大规模 multi-agent 场景

🔧 方法详解

核心架构

AgentScope 1.0 的核心抽象：

  1. MsgHub（消息总线）：agent 间消息传递的统一接口，支持广播和点对点通信
  2. StateModule（状态管理）：统一管理 agent 状态，支持序列化和恢复
  3. Non-Invasive Monitoring：基于 OpenTelemetry 的无侵入式监控

MCP 原生支持

原生集成 MCP（Model Context Protocol）协议： - Agent 可通过 MCP 协议访问外部工具和数据源 - 工具集成不需要修改 agent 代码（non-invasive） - 支持 MCP server 的自动发现和注册

分层记忆系统

  • InMemoryMemory：短期工作记忆，存储当前会话上下文
  • LongTermMemoryBase：长期记忆，支持跨会话信息持久化
  • 记忆检索支持语义搜索和结构化查询

ReAct Agent 内置实现

内置 ReAct 范式的 agent 实现： - Thought → Action → Observation 循环 - 支持自定义 tool 注册 - 内置错误处理和重试机制

分布式调度

  • 基于 gRPC 的分布式通信
  • 支持 agent 在多节点间调度
  • MsgHub 支持分布式消息广播

💡 核心贡献

  1. MCP 原生集成：首个原生支持 MCP 协议的 multi-agent 框架
  2. OpenTelemetry 可观测性：无侵入式监控，适合生产环境
  3. 分层记忆系统：短期 + 长期记忆，支持跨会话持久化
  4. 大规模部署经验：阿里内部大规模 multi-agent 部署验证

🤔 局限性与思考

  1. 框架评估困难：benchmark 上的数字不代表实际开发体验
  2. 与 LangChain 对比不够 fair：只挑了对方弱的场景
  3. 学习曲线：抽象层较多，新手上手成本可能较高
  4. MCP 生态尚未成熟：MCP 协议本身还在快速迭代
