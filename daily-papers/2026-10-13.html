1. Raven: The Harness of Harnesses for Composable Agentic Intelligence

  • 作者: EverMind AI
  • 机构: Raven: The Harness of Harnesses for Composable Agentic Intelligence, Affiliation: 
  • 链接: arXiv | PDF
  • 来源: 🔥 HF Trending，⬆️ 674
  • 核心方法: Raven 提出「harness of harnesses」：通过一个 host 控制多个可执行的 model–harness 对（Raven-Research/Raven-Design/Raven-Code）的分配、信息交换与执行调度。核心贡献是把「可组合智能」形式化——用带类型的执行契约（typed execution contracts）证明确定性组合的 soundness，再推导概率意义上的可靠性边界，以及「组合能力超越单体 agent」的成立条件。
  • 对比方法/Baselines: 对标单一 harness 系统（如 SWE-agent 式专用 harness）与 DeepSeek 等底座 + 固定 harness 的组合。
  • 借鉴意义: 对做 multi-agent 编排的人最有价值的不是又一个框架，而是它给「组合到底能不能更强」这件事提供了可证明的条件——这是从玄学调 prompt 走向工程契约的一步。
  • 锐评: 674 个 upvote 不是白来的：别人在堆 agent，它在给 agent 组合写「类型系统 + 可靠性定理」。真能落地的话是 harness 层的一次范式升级。唯一的保留：形式化契约与真实 LLM 的不确定性之间有多大 gap，摘要没给 empirical 验证的规模，理论漂亮不代表 budget 内真能 cover。先读理论框架部分。🔥

2. AgentScope 1.0: A Developer-Centric Framework for Building Agentic

📒 精读笔记: AgentScope

AgentScope 1.0

📋 基本信息

  • 作者: Dawei Gao, Zitao Li, Yuexiang Xie 等
  • 机构: Alibaba Group
  • 链接: arXiv | PDF

🎯 研究动机与问题

现有 multi-agent 框架（如 LangChain, AutoGen）在以下方面存在不足： 1. 工具集成侵入性强：需要大量修改已有代码 2. 可观测性差：大规模部署时难以监控和调试 3. 长期记忆缺失：agent 无法保持跨会话的上下文 4. 分布式支持弱：难以扩展到大规模 multi-agent 场景

🔧 方法详解

核心架构

AgentScope 1.0 的核心抽象：

  1. MsgHub（消息总线）：agent 间消息传递的统一接口，支持广播和点对点通信
  2. StateModule（状态管理）：统一管理 agent 状态，支持序列化和恢复
  3. Non-Invasive Monitoring：基于 OpenTelemetry 的无侵入式监控

MCP 原生支持

原生集成 MCP（Model Context Protocol）协议： - Agent 可通过 MCP 协议访问外部工具和数据源 - 工具集成不需要修改 agent 代码（non-invasive） - 支持 MCP server 的自动发现和注册

分层记忆系统

  • InMemoryMemory：短期工作记忆，存储当前会话上下文
  • LongTermMemoryBase：长期记忆，支持跨会话信息持久化
  • 记忆检索支持语义搜索和结构化查询

ReAct Agent 内置实现

内置 ReAct 范式的 agent 实现： - Thought → Action → Observation 循环 - 支持自定义 tool 注册 - 内置错误处理和重试机制

分布式调度

  • 基于 gRPC 的分布式通信
  • 支持 agent 在多节点间调度
  • MsgHub 支持分布式消息广播

📊 实验结果

框架 MCP支持 可观测性 长期记忆 分布式
LangChain 部分 弱 第三方 弱
AutoGen 无 弱 无 部分

💡 核心贡献

  1. MCP 原生集成：首个原生支持 MCP 协议的 multi-agent 框架
  2. OpenTelemetry 可观测性：无侵入式监控，适合生产环境
  3. 分层记忆系统：短期 + 长期记忆，支持跨会话持久化
  4. 大规模部署经验：阿里内部大规模 multi-agent 部署验证

🤔 局限性与思考

  1. 框架评估困难：benchmark 上的数字不代表实际开发体验
  2. 与 LangChain 对比不够 fair：只挑了对方弱的场景
  3. 学习曲线：抽象层较多，新手上手成本可能较高
  4. MCP 生态尚未成熟：MCP 协议本身还在快速迭代

📚 相关工作

  • MCP: Model Context Protocol，agent 工具集成标准
  • OpenTelemetry: 可观测性标准
  • ReAct: 推理+行动范式
  • LangChain: 竞品框架
  • AutoGen: 微软 multi-agent 框架
  • 锐评: AgentScope 1.0，阿里的开发者向 agent 框架，你库里已经有笔记了。70 upvote、ReAct + MCP + 分布式那一套，作为「怎么搭 agent 应用」的工程参考仍然值得翻，但技术新意有限，属于基础设施而非研究突破。👀

5. CB-Orchestrator: Adaptive Workflow Optimization for LLM Agents via Contextual Bandits

  • 作者: Jiahang Sun, Zhiwei Shang, Zhipiao Liu, Hongwei Yang, Guoqing Xie, Shuang Qiu, Zhongxiang Dai
  • 机构: ††thanks: Corresponding author. Correspondence to daizhongxiang@cuhk.edu.cn, Affiliation: Huawei Technologies, Affiliation: City University of Hong Kong, Affiliation: , Affiliation: The Chinese University of Hong Kong, Shenzhen

  • 来源: 📄 arXiv 关键词检索
  • 核心方法: CB-Orchestrator 用 contextual bandit（UCB）做 LLM agent 的自适应工作流优化：针对不同 query 动态选择工作流结构，关键是避免现有方法在训练期收集反馈时的昂贵 API 开销。

10. Rollout-Time Intervention: Unlocking Agentic Reinforcement Learning Beyond Policy Limits

  • 作者: Xi Chen, Ruixue Ding, Zhigaoyuan Wang, Fanrui Zhang, Qiang Zhang, Boli Chen, Shihang Wang, Tianfu Wang, Ailin Ren, Pengyong Wang, Pengjun Xie, Hui Xiong
  • 机构: Affiliation: Alibaba Token Hub, Alibaba Group, Affiliation: Amap, Alibaba Group, Affiliation: , Affiliation: HKUST (Guangzhou)
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: RTI（Rollout-Time Intervention）针对 agentic RL 的「on-policy 推理瓶颈」：当任务超出模型当前能力边界时，有效轨迹极度稀疏，GRPO 式训练容易崩。RTI 在 rollout 阶段注入干预，把超出能力边界的任务重新拉回可学习区间，从而解锁「策略极限之外」的训练。
  • 对比方法/Baselines: 对标标准 GRPO 与纯 on-policy 的 agentic RL，在 Claw-Eval、POI 等任务上评估。
  • 借鉴意义: agentic RL 最真实的痛点就是「难任务采不到正样本→训练白跑」，RTI 直接动手术而不是加 reward shaping，对想训 LLM agent 的人是硬核方法论。
  • 锐评: 这才是今天最有技术含量的一篇：不绕弯子，直接指认 on-policy 的死穴然后在 rollout 里动刀。Alibaba Token Hub + Amap 的组合也说明是冲着真实场景去的。质疑点：rollout-time 干预本质是给模型「喂了拐杖」，要警惕它学到的是「有干预才会」而非真能力——off-policy 污染和分布漂移的代价摘要讲得不够。但方向对。🔥

11. Evolving Creatives with Clicks: CTR-Driven Advertising image Editing via Attribute Disentanglement and Preference Alignment

  • 作者: Xu Zhang, Haohan Wang, Zheng Zhang\corresponding, Yingjie Xia, Wei Feng, Honghe Zhu, Jingjing Lv, Changping Peng, Xuheng Qin, Zehua Zhang, Zheng Luo, Qicheng Li\corresponding
  • 机构: TMCC, College of Computer Science, Nankai University, VCIP, Computer Science, Nankai University
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: ECC（Evolving Creatives with Clicks）把电商广告创意优化目标从「好看」改成「点击率」。做法是属性解耦（attribute disentanglement）+ 偏好对齐（DPO/CPO），用 CTR reward 指导对商品图的指令式编辑（Instruction-Guided），而不是从头生成一张图。
  • 对比方法/Baselines: 对标直接用 CTR reward 做 prompt 优化 + RL 生成的方法，以及 DPO/CPO 等偏好对齐基线，用 ANOVA 做显著性分析。
  • 借鉴意义: 这是今天唯一一篇直接命中「广告 + CTR + 生成」三角的论文。对做广告投放/创意自动化的人，属性解耦让「改哪个元素涨 CTR」变得可控、可解释——比黑箱生成更有生产价值。
  • 锐评: 正中靶心的一篇，南开出品，工程味很足：不追求端到端生成的炫技，而是把创意编辑拆成可归因的属性维度再用点击率对齐，这思路在真实广告系统里比「生成一张更美的图」务实得多。保留：CTR 作为 reward 极易过拟合到平台当前流量分布，离线 ANOVA 显著不等于线上长期增量，摘要没提 online A/B。但选题和方法都对味。👀

AgentScope 1.0

📋 基本信息

  • 作者: Dawei Gao, Zitao Li, Yuexiang Xie 等
  • 机构: Alibaba Group
  • 链接: arXiv | PDF

🎯 研究动机与问题

现有 multi-agent 框架（如 LangChain, AutoGen）在以下方面存在不足： 1. 工具集成侵入性强：需要大量修改已有代码 2. 可观测性差：大规模部署时难以监控和调试 3. 长期记忆缺失：agent 无法保持跨会话的上下文 4. 分布式支持弱：难以扩展到大规模 multi-agent 场景

🔧 方法详解

核心架构

AgentScope 1.0 的核心抽象：

  1. MsgHub（消息总线）：agent 间消息传递的统一接口，支持广播和点对点通信
  2. StateModule（状态管理）：统一管理 agent 状态，支持序列化和恢复
  3. Non-Invasive Monitoring：基于 OpenTelemetry 的无侵入式监控

MCP 原生支持

原生集成 MCP（Model Context Protocol）协议： - Agent 可通过 MCP 协议访问外部工具和数据源 - 工具集成不需要修改 agent 代码（non-invasive） - 支持 MCP server 的自动发现和注册

分层记忆系统

  • InMemoryMemory：短期工作记忆，存储当前会话上下文
  • LongTermMemoryBase：长期记忆，支持跨会话信息持久化
  • 记忆检索支持语义搜索和结构化查询

ReAct Agent 内置实现

内置 ReAct 范式的 agent 实现： - Thought → Action → Observation 循环 - 支持自定义 tool 注册 - 内置错误处理和重试机制

分布式调度

  • 基于 gRPC 的分布式通信
  • 支持 agent 在多节点间调度
  • MsgHub 支持分布式消息广播

📊 实验结果

框架 MCP支持 可观测性 长期记忆 分布式
LangChain 部分 弱 第三方 弱

💡 核心贡献

  1. MCP 原生集成：首个原生支持 MCP 协议的 multi-agent 框架
  2. OpenTelemetry 可观测性：无侵入式监控，适合生产环境
  3. 分层记忆系统：短期 + 长期记忆，支持跨会话持久化
  4. 大规模部署经验：阿里内部大规模 multi-agent 部署验证

🤔 局限性与思考

  1. 框架评估困难：benchmark 上的数字不代表实际开发体验
  2. 与 LangChain 对比不够 fair：只挑了对方弱的场景
  3. 学习曲线：抽象层较多，新手上手成本可能较高
  4. MCP 生态尚未成熟：MCP 协议本身还在快速迭代

  • 核心方法: RTI（Rollout-Time Intervention）针对 agentic RL 的「on-policy 推理瓶颈」：当任务超出模型当前能力边界时，有效轨迹极度稀疏，GRPO 式训练容易崩。RTI 在 rollout 阶段注入干预，把超出能力边界的任务重新拉回可学习区间，从而解锁「策略极限之外」的训练。

  • 借鉴意义: agentic RL 最真实的痛点就是「难任务采不到正样本→训练白跑」，RTI 直接动手术而不是加 reward shaping，对想训 LLM agent 的人是硬核方法论。
  • 锐评: 这才是今天最有技术含量的一篇：不绕弯子，直接指认 on-policy 的死穴然后在 rollout 里动刀。Alibaba Token Hub + Amap 的组合也说明是冲着真实场景去的。质疑点：rollout-time 干预本质是给模型「喂了拐杖」，要警惕它学到的是「有干预才会」而非真能力——off-policy 污染和分布漂移的代价摘要讲得不够。但方向对。🔥
