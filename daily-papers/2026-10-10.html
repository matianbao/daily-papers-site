1. RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

  • 作者: Peng Xia, Rujun Han, Zifeng Wang, Yanfei Chen, Yufan Zhuang, Yoonho Lee, Chengsong Huang, Han Yu, Zhongying CuiZhu, Yifei Ming, Huaxiu Yao, Burak Gokturk, Tomas Pfister, Chen-Yu Lee
  • 机构: Affiliation: Washington University in St. Louis, Affiliation:   Stanford University, Affiliation:, * This work was done while Peng was a Student Researcher at Google Cloud AI Research
  • 链接: arXiv | PDF
  • 来源: 🔥 HF Trending，⬆️ 224
  • 核心方法: RRSI 把 agent 建模为 (π, H)——冻结的 backbone 策略 π 加一个 harness H（提示、控制流、工具接口、记忆/技能文件、上下文管理）。核心是对 harness 的迭代式 component-wise 编辑做正则化，防止 RSI 在少数 benchmark 上过拟合、OOD 直接崩。在 Terminal-Bench、SWE、JobBench、EngDesign 等多任务上评估泛化。
  • 对比方法/Baselines: 对比朴素的 APEX 式无约束自我改进与 GEPA 类反射式提示进化。
  • 借鉴意义: 对做 agent 系统的人是直接可用的方法论——RSI 不加约束就是在 benchmark 上刷分、换个分布就废。这篇把『别过拟合你的脚手架』讲清楚了。
  • 锐评: 终于有人承认 RSI 的皇帝新衣：不加正则，所谓『自我改进』就是对评测集的记忆。224 赞不是白来的，它是今天这堆 harness 论文里唯一把过拟合当成一等公民问题处理的。质疑点：正则化本身的超参怎么选？会不会只是把过拟合从 benchmark 转移到了正则项的选择上？但方向绝对正确。🔥

  • 作者: EverMind AI
  • 机构: Affiliation: , Raven: The Harness of Harnesses for Composable Agentic Intelligence

3. SkillOpt: Executive Strategy for Self-Evolving Agent Skills

  • 机构: Fudan University, Microsoft, Shanghai Jiao Tong University, Tongji University
  • 链接: arXiv | PDF

  • 来源: 🔥 HF Trending，⬆️ 267

  • 核心方法: SkillOpt 把 agent skill 当成『冻结 agent 的外部状态』来训练，追求像权重空间优化一样可复现的纪律，而不是手搓、一次性生成或松散自改。在 SpreadsheetBench、SearchQA、LiveMath 上评估。

AgentScope 1.0

  • 作者: Dawei Gao, Zitao Li, Yuexiang Xie 等

🎯 研究动机与问题

现有 multi-agent 框架（如 LangChain, AutoGen）在以下方面存在不足： 1. 工具集成侵入性强：需要大量修改已有代码 2. 可观测性差：大规模部署时难以监控和调试 3. 长期记忆缺失：agent 无法保持跨会话的上下文 4. 分布式支持弱：难以扩展到大规模 multi-agent 场景

🔧 方法详解

核心架构

AgentScope 1.0 的核心抽象：

  1. MsgHub（消息总线）：agent 间消息传递的统一接口，支持广播和点对点通信
  2. StateModule（状态管理）：统一管理 agent 状态，支持序列化和恢复
  3. Non-Invasive Monitoring：基于 OpenTelemetry 的无侵入式监控

MCP 原生支持

原生集成 MCP（Model Context Protocol）协议： - Agent 可通过 MCP 协议访问外部工具和数据源 - 工具集成不需要修改 agent 代码（non-invasive） - 支持 MCP server 的自动发现和注册

分层记忆系统

  • InMemoryMemory：短期工作记忆，存储当前会话上下文
  • LongTermMemoryBase：长期记忆，支持跨会话信息持久化
  • 记忆检索支持语义搜索和结构化查询

ReAct Agent 内置实现

内置 ReAct 范式的 agent 实现： - Thought → Action → Observation 循环 - 支持自定义 tool 注册 - 内置错误处理和重试机制

分布式调度

  • 基于 gRPC 的分布式通信
  • 支持 agent 在多节点间调度
  • MsgHub 支持分布式消息广播

  4. MCP 生态尚未成熟：MCP 协议本身还在快速迭代

7. When Should Agents Think? Adaptive Reasoning via Cross-Turn Estimation

  • 作者: Cheng, Yiruo, Huang, Shen, Song, Xiaoshuai, Tan, Jiejun, Dong, Guanting, Xie, Pengjun, Wen, Ji-Rong, Dou, Zhicheng
  • 机构: Renmin University of China, ††thanks: Work done during internship at Alibaba Token Hub, Alibaba Group††thanks: Corresponding author, 1Gaoling School of Artificial Intelligence, 2Alibaba Token Hub, Alibaba Group
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: RACE（Adaptive Reasoning via Cross-Turn Estimation）发现 agent 不必每一轮 action 前都重新推理——早先产生的 reasoning 能继续支撑后续动作。通过 LoGiC 这个轻量信号跨轮估计何时真的需要重新 think，避免重复 action 生成。在 AppWorld、WebShop、ScienceWorld 上验证。
  • 对比方法/Baselines: 对比每轮都推理的 ReAct 式默认策略与 SFT/RL 基线。
  • 借鉴意义: 直接砍 agent 的推理 token 开销，对部署成本敏感的场景（高频 tool-use agent）非常实在。
  • 锐评: 一个被大多数人忽略的常识被认真量化了：reasoning 有惯性，不是每步都要从头想。『跨轮估计 + 轻量信号』比那些动辄要再训一个 critic 的方案务实得多。质疑点：LoGiC 信号在长程、分布漂移任务上会不会误判，该 think 的时候偷懒？但省 token 这件事做对了就是真金白银。👀

📒 精读笔记: LLM-MAS Simulation

Optimizing Service Operations via LLM-Powered Multi-Agent Simulation

一句话总结：提出 LLM-MAS 框架，将 LLM 多智能体仿真建模为受控马尔可夫链上的随机优化问题，通过零阶梯度的 on-trajectory learning 算法在单次仿真中同时估计梯度和更新设计参数，优化服务系统运营。

1. 研究动机与问题定义

核心问题

服务系统（供应链、竞赛设计、数字市场等）的性能取决于参与者对设计选择的响应，但人类行为建模极其困难： - 分析模型（效用函数等）过度简化，难以捕捉行为偏差 - 实验数据采集成本高（实验室/实地实验） - 人类决策受认知局限影响，偏离完全理性假设

创新思路

用 LLM 作为人类行为的 "硅基代理"（silicon proxy），在多智能体仿真中模拟人类决策。与传统 Agent-Based Modeling 不同，LLM-MAS 不需要手工编写行为规则，而是利用 LLM 预训练中习得的人类行为统计模式。

2. 方法详解

2.1 问题建模：决策依赖不确定性

将系统设计优化建模为决策依赖不确定性（decision-dependent uncertainty）下的随机优化：

$$\min_{\theta \in \Theta} \left\{ f(\theta) \coloneqq \mathbb{E}_{\xi \sim \mu_\theta} [F(\theta; \xi)] \right\}$$

其中： - $\theta \in \Theta \subseteq \mathbb{R}^d$ 为设计参数向量 - $\xi \in \Xi$ 为系统不确定性（智能体行为 + 系统结果） - $\mu_\theta$ 为给定设计 $\theta$ 下 $\xi$ 的稳态分布 - $F(\theta; \xi)$ 为成本函数

关键特点：$\theta$ 嵌入在 prompt 中，改变 token 概率分布，进而影响智能体行为，使得 $\mu_\theta$ 随 $\theta$ 变化。

2.2 受控马尔可夫链建模

将 LLM-MAS 的状态演化建模为受控 Markov Chain：

$$\xi_{n+1} \sim P_\theta(\cdot \mid \xi_n)$$

其中 $P_\theta$ 为给定设计 $\theta$ 下的转移核。系统状态 $\xi$ 通过从 LLM prompt 和 response 中提取紧凑的数值变量构建。

2.3 零阶梯度估计

由于 $\mu_\theta$ 的解析形式不可得，使用零阶方法（Zeroth-Order Optimization）构建梯度估计：

$$\hat{g}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u$$

其中 $u$ 为随机扰动方向，$\delta > 0$ 为扰动步长，$\xi^+, \xi^-$ 分别在 $\theta + \delta u$ 和 $\theta - \delta u$ 下采样。

2.4 On-Trajectory Learning 算法

核心创新——在单次仿真运行中同时完成梯度估计和参数更新，使用双时间尺度（two-timescale）方案：

$$\theta_{n+1} = \Pi_\Theta \left[ \theta_n - \alpha_n \hat{g}_n \right]$$

其中 $\Pi_\Theta$ 为投影算子，$\alpha_n$ 为步长序列。快时间尺度运行仿真生成数据，慢时间尺度更新设计参数。

与标准多轨迹方法（需要多次完整仿真）相比，on-trajectory learning 从整条状态路径学习，大幅减少 LLM 查询次数。

2.5 方差缩减技术

引入两种方差缩减方法：

引导扰动（Guided Perturbation）：利用成本函数 $F$ 的已知结构，将扰动集中在不确定性大的维度：

$$\hat{g}^{\text{GP}}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u + \nabla_\theta F(\theta; \bar{\xi})$$

残差反馈（Residual Feedback）：在结构未知时，利用历史迭代信息减少方差。

2.6 收敛性分析

通过 Stochastic Approximation 的 Poisson 方程方法证明算法收敛：

定理（渐近收敛）：在适当的步长条件和马尔可夫链混合条件下，on-trajectory learning 算法满足：

$$\theta_n \to \theta^* \quad \text{a.s.}$$

其中 $\theta^*$ 为稳态目标函数 $f(\theta)$ 的驻点。

3.1 可持续供应链实验

三层供应链（制造商 M、零售商 R、消费者 C），设计参数为碳税 $\theta_1$ 和消费者补贴 $\theta_2$。

3.2 竞赛设计案例研究

5. 核心概念

  • Controlled Markov Chain：将 LLM-MAS 的状态演化建模为设计参数控制的马尔可夫链
  • Zeroth-Order Optimization：无需梯度的优化方法，通过函数值估计梯度
  • Stochastic Approximation：随机逼近理论，on-trajectory learning 的收敛性证明基础
  • Poisson Equation：用于分析马尔可夫数据时间依赖性的工具
  • Agent-Based Modeling：基于微观行为涌现宏观动态的建模范式
  • Decision-Dependent Uncertainty：不确定性分布随决策变量变化的优化问题

6. 优缺点分析

优点

  1. 理论贡献扎实：将 LLM-MAS 形式化为受控马尔可夫链，提供了严格的数学框架
  2. 算法高效：on-trajectory learning 在单次仿真中完成，避免了多轨迹方法的高昂 LLM 推理成本
  3. 收敛保证：提供了渐近收敛的理论证明
  4. 方差缩减：两种技术分别适用于结构已知和未知场景
  5. 实证验证：真实行为数据的竞赛设计案例增强说服力
  6. 可解释性：LLM 推理过程提供了决策逻辑的透明度

缺点

  1. 核心假设脆弱：LLM 行为分布与真实人类的差距未被正面回答
  2. 仅用开源模型：未在 GPT-4/Claude 等更强模型上验证
  3. 应用场景有限：仅测试了供应链和竞赛设计两个场景
  4. 马尔可夫假设：实际人类决策可能具有长期记忆，违反马尔可夫性
  5. 不做微调：假设 LLM "开箱即用" 即可准确模拟人类行为，但不同文化/人群的行为差异如何处理？
  6. 计算成本：虽然比多轨迹方法高效，但 LLM 推理仍然昂贵

📒 精读笔记: LLM-MAS Simulation

Optimizing Service Operations via LLM-Powered Multi-Agent Simulation

一句话总结：提出 LLM-MAS 框架，将 LLM 多智能体仿真建模为受控马尔可夫链上的随机优化问题，通过零阶梯度的 on-trajectory learning 算法在单次仿真中同时估计梯度和更新设计参数，优化服务系统运营。

1. 研究动机与问题定义

核心问题

服务系统（供应链、竞赛设计、数字市场等）的性能取决于参与者对设计选择的响应，但人类行为建模极其困难： - 分析模型（效用函数等）过度简化，难以捕捉行为偏差 - 实验数据采集成本高（实验室/实地实验） - 人类决策受认知局限影响，偏离完全理性假设

创新思路

用 LLM 作为人类行为的 "硅基代理"（silicon proxy），在多智能体仿真中模拟人类决策。与传统 Agent-Based Modeling 不同，LLM-MAS 不需要手工编写行为规则，而是利用 LLM 预训练中习得的人类行为统计模式。

2. 方法详解

2.1 问题建模：决策依赖不确定性

将系统设计优化建模为决策依赖不确定性（decision-dependent uncertainty）下的随机优化：

$$\min_{\theta \in \Theta} \left\{ f(\theta) \coloneqq \mathbb{E}_{\xi \sim \mu_\theta} [F(\theta; \xi)] \right\}$$

其中： - $\theta \in \Theta \subseteq \mathbb{R}^d$ 为设计参数向量 - $\xi \in \Xi$ 为系统不确定性（智能体行为 + 系统结果） - $\mu_\theta$ 为给定设计 $\theta$ 下 $\xi$ 的稳态分布 - $F(\theta; \xi)$ 为成本函数

关键特点：$\theta$ 嵌入在 prompt 中，改变 token 概率分布，进而影响智能体行为，使得 $\mu_\theta$ 随 $\theta$ 变化。

2.2 受控马尔可夫链建模

将 LLM-MAS 的状态演化建模为受控 Markov Chain：

$$\xi_{n+1} \sim P_\theta(\cdot \mid \xi_n)$$

其中 $P_\theta$ 为给定设计 $\theta$ 下的转移核。系统状态 $\xi$ 通过从 LLM prompt 和 response 中提取紧凑的数值变量构建。

2.3 零阶梯度估计

由于 $\mu_\theta$ 的解析形式不可得，使用零阶方法（Zeroth-Order Optimization）构建梯度估计：

$$\hat{g}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u$$

其中 $u$ 为随机扰动方向，$\delta > 0$ 为扰动步长，$\xi^+, \xi^-$ 分别在 $\theta + \delta u$ 和 $\theta - \delta u$ 下采样。

2.4 On-Trajectory Learning 算法

核心创新——在单次仿真运行中同时完成梯度估计和参数更新，使用双时间尺度（two-timescale）方案：

$$\theta_{n+1} = \Pi_\Theta \left[ \theta_n - \alpha_n \hat{g}_n \right]$$

其中 $\Pi_\Theta$ 为投影算子，$\alpha_n$ 为步长序列。快时间尺度运行仿真生成数据，慢时间尺度更新设计参数。

与标准多轨迹方法（需要多次完整仿真）相比，on-trajectory learning 从整条状态路径学习，大幅减少 LLM 查询次数。

2.5 方差缩减技术

引入两种方差缩减方法：

引导扰动（Guided Perturbation）：利用成本函数 $F$ 的已知结构，将扰动集中在不确定性大的维度：

$$\hat{g}^{\text{GP}}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u + \nabla_\theta F(\theta; \bar{\xi})$$

残差反馈（Residual Feedback）：在结构未知时，利用历史迭代信息减少方差。

2.6 收敛性分析

通过 Stochastic Approximation 的 Poisson 方程方法证明算法收敛：

定理（渐近收敛）：在适当的步长条件和马尔可夫链混合条件下，on-trajectory learning 算法满足：

$$\theta_n \to \theta^* \quad \text{a.s.}$$

其中 $\theta^*$ 为稳态目标函数 $f(\theta)$ 的驻点。

3. 实验结果

3.1 可持续供应链实验

三层供应链（制造商 M、零售商 R、消费者 C），设计参数为碳税 $\theta_1$ 和消费者补贴 $\theta_2$。

3.2 竞赛设计案例研究

使用 Huang et al. (2026) 的真实行为实验数据验证： - LLM-MAS 成功复现了异质性人类行为（是否参赛、努力程度与能力的关系） - 跨不同竞赛设计（入场费、保底奖、共享奖金）均保持相似性 - 实验室数据和 LLM-MAS 均显著偏离博弈论预测

5. 核心概念

  • Controlled Markov Chain：将 LLM-MAS 的状态演化建模为设计参数控制的马尔可夫链
  • Zeroth-Order Optimization：无需梯度的优化方法，通过函数值估计梯度
  • Stochastic Approximation：随机逼近理论，on-trajectory learning 的收敛性证明基础
  • Poisson Equation：用于分析马尔可夫数据时间依赖性的工具
  • Agent-Based Modeling：基于微观行为涌现宏观动态的建模范式
  • Decision-Dependent Uncertainty：不确定性分布随决策变量变化的优化问题

6. 优缺点分析

优点

  1. 理论贡献扎实：将 LLM-MAS 形式化为受控马尔可夫链，提供了严格的数学框架
  2. 算法高效：on-trajectory learning 在单次仿真中完成，避免了多轨迹方法的高昂 LLM 推理成本
  3. 收敛保证：提供了渐近收敛的理论证明
  4. 方差缩减：两种技术分别适用于结构已知和未知场景
  5. 实证验证：真实行为数据的竞赛设计案例增强说服力
  6. 可解释性：LLM 推理过程提供了决策逻辑的透明度

缺点

  1. 核心假设脆弱：LLM 行为分布与真实人类的差距未被正面回答
  2. 仅用开源模型：未在 GPT-4/Claude 等更强模型上验证
  3. 应用场景有限：仅测试了供应链和竞赛设计两个场景
  4. 马尔可夫假设：实际人类决策可能具有长期记忆，违反马尔可夫性
  5. 不做微调：假设 LLM "开箱即用" 即可准确模拟人类行为，但不同文化/人群的行为差异如何处理？
  6. 计算成本：虽然比多轨迹方法高效，但 LLM 推理仍然昂贵
