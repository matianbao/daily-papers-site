1. OPID: On-Policy Skill Distillation for Agentic Reinforcement Learning

  • 作者: Shuo Yang1
  • 机构: 1Tsinghua University   2Zhejiang University   3The Chinese University of Hong Kong, Corresponding to: wu-jy23@mails.tsinghua.edu.cn, 4Nanyang Technological University   5Tongji University
  • 链接: arXiv | PDF

  • 来源: 📰 HF Daily，⬆️ 21

  • 核心方法: OPID 针对 agentic RL 中 GRPO 这类 outcome-based 方法奖励稀疏的问题，用 on-policy self-distillation 提供 dense 的 token-level 监督。关键差异是它不依赖外部 skill memory 或检索特权信息，而是直接从策略自身蒸馏技能信号。

  • 对比方法/Baselines: 对标 GRPO、各类 skill-conditioned on-policy distillation 变体，在 WebShop 等 agent 环境上验证。
  • 借鉴意义: 对做 LLM agent RL 训练的人是直接可用的 trick——稀疏 trajectory reward 不知道该奖励哪一步，是当前 agentic RL 最现实的痛点。
  • 锐评: 终于有人不再往 skill memory 里堆外部记忆了。On-policy 自蒸馏拿到 dense 信号这个方向是对的，但 self-distillation 最怕的就是策略自己强化自己的错误——摘要没说怎么防止 mode collapse，得看正文有没有真招。方向干净，先收。🔥

2. Why Multi-Step Tool-Use Reinforcement Learning Collapses and How Supervisory Signals Fix It

  • 作者: Yupu Hao1,2
  • 机构: 1The Key Laboratory of Cognition and Decision Intelligence for Complex Systems, Institute of Automation, Chinese Academy of Sciences, Beijing, China, 2School of Artificial Intelligence, University of Chinese Academy of Sciences, Beijing, China
  • 链接: arXiv | PDF
  • 来源: 📰 HF Daily，⬆️ 7
  • 核心方法: 本文实测发现多步 tool-use 的 RL 训练会出现 catastrophic collapse：性能突然暴跌、tool-invocation 结构直接失效。作者诊断了崩溃机理，并用 SFT 类监督信号去修复，证明纯 RL 在 tool-use 上不稳是结构性问题。

  • 借鉴意义: 如果你训过 tool-use agent 然后莫名其妙跑崩了，这篇就是你的事故报告。把'为什么崩'讲清楚比再发一个新算法有用。
  • 锐评: 标题就是 senior 该问的问题——不吹新 SOTA，先把'为什么会崩'讲明白。这种把失败模式摊开来的论文比第 100 个 GRPO 变体值钱。唯一担心是'监督信号修复'会不会只是把 RL 退化成 SFT，那等于承认 RL 没用。带着这个怀疑读。🔥

3. GEOALIGN: Geometric Rollout Curation for Robust LLM Reinforcement Learning

  • 作者: Ting Zhou, Zhenqing Ling, Yiyang Zhao, Ying Shen, Daoyuan Chen
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: GeoAlign 发现 online RLHF 中存在 directional inconsistency：一个 batch 里少数高奖励 rollout 在表示空间诱导的偏好方向，跟 batch 多数派尖锐冲突，导致高方差和训练失稳。方法是做几何 rollout curation，按方向一致性剔除毒样本。
  • 对比方法/Baselines: 对比 GRPO、PPO、reward clipping/shaping 等稳定性修补手段。
  • 借鉴意义: 和 OPID、Tool-Use Collapse 同一战场——都在治 RL 不稳，但 GeoAlign 的切入点（表示空间方向）最新颖。
  • 锐评: 从表示空间的几何方向去识别'毒 rollout'，这个 framing 比单纯 reward clipping 高级。但 directional inconsistency 到底是噪声还是真信号？多数派方向就一定对吗？万一少数派才是探索到的好策略，按一致性剔除等于扼杀探索。理论 framing 漂亮，实证要看它有没有自己回答这个反驳。👀

4. Reinforcement Learning without Ground-Truth Solutions can Improve LLMs

  • 作者: Yingyu Lin1,2
  • 机构: 1University of California, San Diego  2Snowflake AI Research
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: RiVER（Ranking-induced VERifiable framework）解决 RLVR 必须依赖 ground-truth 答案的限制：在没有标准解的 score-based 优化任务上，用确定性的排序信号代替绝对正确性 reward 来训练 LLM。

  • 对比方法/Baselines: 对标依赖 ground-truth 的 GRPO/RLVR，在 LiveCodeBench、AtCoder、USACO 等竞赛任务上验证。
  • 借鉴意义: 把 RLVR 从'必须有标准答案'解放出来，对开放式任务的 RL 训练是有意义的扩展。
  • 锐评: 用排序代替绝对奖励，思路对——很多真实任务只有相对好坏没有标准解。但'排序信号'本身从哪来？如果还是要一个能排序的 verifier，那只是把 ground-truth 的问题换了个马甲。能不能真正去掉人工标注是关键，别又是套娃。👀

5. Localizing RL-Induced Tool Use to a Single Crosscoder Feature

  • 作者: Andrii Shportko, Shubham Bhokare, Ahmed Zeyad A Alzahrani, Bowen Cheng, Gustavo Mercier, Jessica Hullman
  • 机构: Jessica Hullman
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 本文用 crosscoder（含 Tied 和 Dedicated Feature 三种架构）对 RL 微调前后的配对激活做联合稀疏分解，发现 RL 诱导的 tool-use 行为可以定位到单个 CrossCoder 特征，并且能用它做 retraining-free 的行为控制。
  • 对比方法/Baselines: 基于 SAE/mechanistic interpretability 传统方法（Bricken/Cunningham/Templeton 系），在 ToolRL 微调模型上分析。
  • 借鉴意义: 把'RL 到底改了模型什么'从黑盒变成可定位、可干预的单个特征——对理解和控制 agentic 行为是真正的洞察，不是又一个 benchmark。
  • 锐评: 这才是有意思的工作：不问'能不能更强'，而问'RL 到底在脑子里改了哪根神经'。把 tool-use 收敛到单个 crosscoder feature，还能不重训直接控制行为——如果可复现，这对安全和可控性都是干货。质疑点：单特征定位会不会是 cherry-picked 的漂亮案例？换个模型还成立吗。但选题本身就赢了。🔥

6. Instruction Bleed: Cross-Module Interference in Prompt-Composed Agentic Systems

  • 作者: Ching-Yu Lin, Yifan Liu
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 本文形式化了一个工程界都遇到过的现象——compositional behavioral leakage（CBL）：改一个 prompt 模块会悄悄改变其他模块的行为，即使它们没有共享变量或可执行依赖。根因是 transformer self-attention 对拼接在同一 context window 里的模块不提供任何形式边界（architectural non-isolation）。

  • 对比方法/Baselines: 在 OpenHands、prompt-composed agentic 系统上实证，涉及 CLAUDE.md 类 context 文件。
  • 借鉴意义: 凡是维护过多模块 system prompt 的人都被这个坑过——这篇给了它一个名字和机理解释，对 agent 系统设计有指导意义。
  • 锐评: 小而准。把'改了 A 的 prompt，B 莫名其妙变了'这个玄学现象归因到 self-attention 没有模块边界，一针见血。这不是惊天算法，但它命名并解释了一个真实工程痛点，比很多堆指标的论文有用。缺点是诊断完了——有没有给出隔离方案？还是只停在'我们发现了一个问题'。👀

📒 精读笔记: LLM-MAS Simulation

Optimizing Service Operations via LLM-Powered Multi-Agent Simulation

一句话总结：提出 LLM-MAS 框架，将 LLM 多智能体仿真建模为受控马尔可夫链上的随机优化问题，通过零阶梯度的 on-trajectory learning 算法在单次仿真中同时估计梯度和更新设计参数，优化服务系统运营。

1. 研究动机与问题定义

核心问题

服务系统（供应链、竞赛设计、数字市场等）的性能取决于参与者对设计选择的响应，但人类行为建模极其困难： - 分析模型（效用函数等）过度简化，难以捕捉行为偏差 - 实验数据采集成本高（实验室/实地实验） - 人类决策受认知局限影响，偏离完全理性假设

创新思路

用 LLM 作为人类行为的 "硅基代理"（silicon proxy），在多智能体仿真中模拟人类决策。与传统 Agent-Based Modeling 不同，LLM-MAS 不需要手工编写行为规则，而是利用 LLM 预训练中习得的人类行为统计模式。

2. 方法详解

2.1 问题建模：决策依赖不确定性

将系统设计优化建模为决策依赖不确定性（decision-dependent uncertainty）下的随机优化：

$$\min_{\theta \in \Theta} \left\{ f(\theta) \coloneqq \mathbb{E}_{\xi \sim \mu_\theta} [F(\theta; \xi)] \right\}$$

其中： - $\theta \in \Theta \subseteq \mathbb{R}^d$ 为设计参数向量 - $\xi \in \Xi$ 为系统不确定性（智能体行为 + 系统结果） - $\mu_\theta$ 为给定设计 $\theta$ 下 $\xi$ 的稳态分布 - $F(\theta; \xi)$ 为成本函数

关键特点：$\theta$ 嵌入在 prompt 中，改变 token 概率分布，进而影响智能体行为，使得 $\mu_\theta$ 随 $\theta$ 变化。

2.2 受控马尔可夫链建模

将 LLM-MAS 的状态演化建模为受控 Markov Chain：

$$\xi_{n+1} \sim P_\theta(\cdot \mid \xi_n)$$

其中 $P_\theta$ 为给定设计 $\theta$ 下的转移核。系统状态 $\xi$ 通过从 LLM prompt 和 response 中提取紧凑的数值变量构建。

2.3 零阶梯度估计

由于 $\mu_\theta$ 的解析形式不可得，使用零阶方法（Zeroth-Order Optimization）构建梯度估计：

$$\hat{g}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u$$

其中 $u$ 为随机扰动方向，$\delta > 0$ 为扰动步长，$\xi^+, \xi^-$ 分别在 $\theta + \delta u$ 和 $\theta - \delta u$ 下采样。

2.4 On-Trajectory Learning 算法

核心创新——在单次仿真运行中同时完成梯度估计和参数更新，使用双时间尺度（two-timescale）方案：

$$\theta_{n+1} = \Pi_\Theta \left[ \theta_n - \alpha_n \hat{g}_n \right]$$

其中 $\Pi_\Theta$ 为投影算子，$\alpha_n$ 为步长序列。快时间尺度运行仿真生成数据，慢时间尺度更新设计参数。

与标准多轨迹方法（需要多次完整仿真）相比，on-trajectory learning 从整条状态路径学习，大幅减少 LLM 查询次数。

2.5 方差缩减技术

引入两种方差缩减方法：

引导扰动（Guided Perturbation）：利用成本函数 $F$ 的已知结构，将扰动集中在不确定性大的维度：

$$\hat{g}^{\text{GP}}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u + \nabla_\theta F(\theta; \bar{\xi})$$

残差反馈（Residual Feedback）：在结构未知时，利用历史迭代信息减少方差。

2.6 收敛性分析

通过 Stochastic Approximation 的 Poisson 方程方法证明算法收敛：

定理（渐近收敛）：在适当的步长条件和马尔可夫链混合条件下，on-trajectory learning 算法满足：

$$\theta_n \to \theta^* \quad \text{a.s.}$$

其中 $\theta^*$ 为稳态目标函数 $f(\theta)$ 的驻点。

三层供应链（制造商 M、零售商 R、消费者 C），设计参数为碳税 $\theta_1$ 和消费者补贴 $\theta_2$。

5. 核心概念

  • Controlled Markov Chain：将 LLM-MAS 的状态演化建模为设计参数控制的马尔可夫链
  • Zeroth-Order Optimization：无需梯度的优化方法，通过函数值估计梯度

6. 优缺点分析

优点

  1. 理论贡献扎实：将 LLM-MAS 形式化为受控马尔可夫链，提供了严格的数学框架
  2. 算法高效：on-trajectory learning 在单次仿真中完成，避免了多轨迹方法的高昂 LLM 推理成本
  3. 收敛保证：提供了渐近收敛的理论证明
  4. 方差缩减：两种技术分别适用于结构已知和未知场景
  5. 实证验证：真实行为数据的竞赛设计案例增强说服力
  6. 可解释性：LLM 推理过程提供了决策逻辑的透明度

缺点

  1. 核心假设脆弱：LLM 行为分布与真实人类的差距未被正面回答
  2. 仅用开源模型：未在 GPT-4/Claude 等更强模型上验证
  3. 应用场景有限：仅测试了供应链和竞赛设计两个场景
  4. 马尔可夫假设：实际人类决策可能具有长期记忆，违反马尔可夫性
  5. 不做微调：假设 LLM "开箱即用" 即可准确模拟人类行为，但不同文化/人群的行为差异如何处理？
  6. 计算成本：虽然比多轨迹方法高效，但 LLM 推理仍然昂贵

一句话总结

首个大规模实证研究，分析 2,303 个 Agent 上下文文件（CLAUDE.md/AGENTS.md/copilot-instructions.md）的结构、维护模式与指令内容，揭示功能性指令主导而安全/性能等非功能性需求严重缺失的现状。

核心贡献

  1. 首个大规模 Agent 上下文文件实证研究: 收集 1,925 个仓库中的 2,303 个 Agent 上下文文件（ACF），覆盖 Claude Code、OpenAI Codex、GitHub Copilot 三大工具
  2. 16 类指令分类体系: 通过人工标注构建 Agent 上下文文件的指令分类 taxonomy，发现功能性指令（Build and Run 62.3%、Implementation Details 69.9%）远多于非功能性需求（Security 14.5%、Performance 14.5%）
  3. 自动分类可行性验证: 使用 GPT-5 实现 0.79 F1-score 的自动分类，证明大规模监控 Agent 上下文文件的可行性

问题背景

要解决的问题

Agentic Coding 工具（如 Claude Code、OpenAI Codex、GitHub Copilot）依赖 Agent 上下文文件（ACF）来理解项目架构、遵循编码规范、执行构建测试。但目前缺乏关于这些文件结构、演化方式和实际内容的系统性实证证据。

现有方法的局限

  • 官方文档仅提供高层指导（如"描述架构和工作流"），开发者只能通过试错来设计这些文件
  • 已有研究主要关注 LLM 的模型能力、交互模式和即时提示，而非持久化的项目级上下文配置
  • 前序工作 (Chatlatanagulchai et al., 2025) 仅研究了 253 个 Claude Code 文件，范围有限

本文的动机

Agent 上下文文件作为一种新型软件工件（"READMEs for agents"），在 Agentic Coding 生态中扮演关键角色，但学术界对其缺乏基本的经验性认知。本文旨在通过大规模实证分析填补这一空白。

方法详解

研究设计

本文围绕四个研究问题（RQ）展开：

  • RQ1: Agent 上下文文件的特征（大小、可读性、结构）是什么？
  • RQ2: 开发者维护 Agent 上下文文件的频率如何？
  • RQ3: Agent 上下文文件包含哪些指令？
  • RQ4: 能否自动分类 Agent 上下文文件中的指令？

数据收集

数据来源: AIDev 数据集 (Li et al., 2025b)，筛选 GitHub Stars ≥ 5 的 8,370 个仓库

文件检索: 通过 GitHub API 扫描仓库根目录，按官方命名规范检索： - CLAUDE.md → Claude Code（922 个） - AGENTS.md → OpenAI Codex（694 个） - copilot-instructions.md → GitHub Copilot（687 个） - 总计: 2,303 个文件来自 1,925 个仓库

RQ1: 特征分析方法

  • 大小: 正则表达式 \w+ 匹配单词数
  • 可读性: FRE 指标（越高越易读）
  • 结构: 统计 Markdown 标题层级（H1-H5）分布
  • 统计检验: Mann-Whitney U Test + Cliff's Delta 效应量

RQ2: 维护模式分析

  • 提取所有修改 ACF 的 commit 历史
  • 统计 commit 数量、时间间隔、增删行数
  • 总计分析 5,655（Claude Code）+ 2,767（Codex）+ 2,237（Copilot）= 10,659 次 commit

RQ3: 内容分类方法

两阶段人工标注:

  1. 标签创建阶段: 提取 H1/H2 标题 → 3 个 LLM（Claude Opus 4.1、Gemini 2.5 Pro、GPT-5）生成候选标签 → 人工筛选 → 80 个初始标签 → 合并为 16 个核心类别
  2. 标签分配阶段: 2 位标注员独立标注 332 个 Claude Code 文件 → 80.3% 一致率 → 第 3 位标注员调解分歧 → 最终 2,069 个标签分配

RQ4: 自动分类方法

  • 任务: 多标签分类（16 个类别）
  • 模型: GPT-5
  • 输入: 完整 ACF 内容 + 每个类别的描述和示例
  • 评估: Precision / Recall / F1-score（per-category + micro average）

关键公式

公式1: 效应量判断标准

$$ \text{Effect size} = \begin{cases} \text{negligible}, & \text{if } |d| \leq 0.147 \\ \text{small}, & \text{if } 0.147 < |d| \leq 0.33 \\ \text{medium}, & \text{if } 0.33 < |d| \leq 0.474 \\ \text{large}, & \text{if } 0.474 < |d| \leq 1 \end{cases} $$

含义: 用 Cliff's delta $d$ 量化两组样本之间差异的实际显著性，补充 Mann-Whitney U Test 的统计显著性判断

符号说明: - $d$: Cliff's delta 值，范围 $[-1, 1]$ - $|d|$: delta 的绝对值

公式2: Flesch Reading Ease

$$ FRE = 206.835 - 1.015 \times \frac{\text{total words}}{\text{total sentences}} - 84.6 \times \frac{\text{total syllables}}{\text{total words}} $$

含义: 衡量文本可读性，分数越高越容易阅读（0-100 范围）

符号说明: - $FRE$: Flesch Reading Ease 分数 - 低于 30 为 "Very Difficult"（大学毕业生水平） - 30-50 为 "Difficult"（大学水平）

实现细节

  • 标注工具: LLM 辅助标签生成（Claude Opus 4.1、Gemini 2.5 Pro、GPT-5）
  • 统计检验: Mann-Whitney U test ($\alpha = 0.05$) + Cliff's delta 效应量
  • 可读性指标: Flesch Reading Ease (FRE)
  • 分类评估: Precision / Recall / F1-score (micro average)
  • 标注员: 3 位检查员，编程经验 4-17 年

核心发现汇总

RQ1 — 特征: - ACF 普遍长且难读，Claude Code 最难读（FRE 中位数 16.6） - 一致的浅层层级结构：单一 H1 + H2/H3 组织

RQ2 — 维护: - 67.4% 的 Claude Code ACF 经历多次修改，不是静态文档 - 维护以短时间突发模式进行（中位间隔约 1 天） - 演化由小规模增量添加驱动

RQ3 — 内容: - 功能性指令占主导（Testing 75.0%、Impl. Details 69.9%、Architecture 67.7%） - 非功能性需求严重不足（Security 14.5%、Performance 14.5%）

RQ4 — 自动分类: - GPT-5 达到 0.79 F1-score，具体功能类别效果好（Testing 0.94） - 抽象类别效果较差（Maintenance 0.56、Project Management 0.42）

批判性思考

优点

  1. 规模全面: 2,303 个文件、1,925 个仓库、3 种工具，是该领域迄今最大规模的实证研究
  2. 实践价值高: 16 类指令 taxonomy 直接可用于指导 ACF 编写和工具设计
  3. 方法严谨: 多标注员独立标注 + 调解机制，Mann-Whitney U + Cliff's delta 双重统计检验
  4. 洞察深刻: 揭示了 "功能性 vs 非功能性" 指令的显著失衡，对安全和性能有重要警示意义
  5. 可复现: 提供完整 replication package

局限性

  1. 仅分析根目录文件: 可能遗漏子目录中的 ACF（如 .github/copilot-instructions.md）
  2. 二值分类局限: 仅标记类别是否出现，未衡量指令的深度和质量
  3. 仅限开源项目: 企业内部的 ACF 实践可能有显著不同
  4. 人工标注仅覆盖 Claude Code: 332 个文件的标注结果用于推广到全部 2,303 个文件可能存在偏差

潜在改进方向

  1. 纵向追踪研究: 分析 ACF 与代码变更的 co-evolution 关系
  2. 因果分析: 研究 ACF 内容质量对 Agent 生成代码质量的影响
  3. 模板设计: 基于 16 类 taxonomy 设计标准化 ACF 模板
  4. 非功能性需求检测: 开发 CI 集成工具自动检测 ACF 中缺失的 Security/Performance 指令

Mem0

定义

一个开源的 AI 记忆层框架，为 LLM 应用提供持久化的用户/会话记忆管理，支持记忆的自动提取、存储、检索和更新。

核心要点

  1. 从对话中自动提取关键信息并存储为结构化记忆
  2. 支持多级记忆：用户级、会话级、Agent 级
  3. 基于向量检索实现相关记忆的上下文注入
  4. 与 Zep 等系统的区别：更轻量，侧重 key-value 式记忆而非图结构

Zep

定义

一个 AI 记忆管理平台，使用知识图谱和时序模型为 LLM Agent 提供长期记忆能力，支持事实提取、关系建模和记忆演化。

核心要点

  2. 支持 Bi-temporal Model——区分事实发生时间和记录时间
  3. 自动从对话中提取实体、关系和事件，构建动态图谱
  4. 与 Mem0 的区别：更重量级，适合需要复杂关系推理的场景

1. OPID: On-Policy Skill Distillation for Agentic Reinforcement Learning

  • 作者: Shuo Yang1
  • 机构: 1Tsinghua University   2Zhejiang University   3The Chinese University of Hong Kong, Corresponding to: wu-jy23@mails.tsinghua.edu.cn, 4Nanyang Technological University   5Tongji University
  • 链接: arXiv | PDF

  • 来源: 📰 HF Daily，⬆️ 21

  • 核心方法: OPID 针对 agentic RL 中 GRPO 这类 outcome-based 方法奖励稀疏的问题，用 on-policy self-distillation 提供 dense 的 token-level 监督。关键差异是它不依赖外部 skill memory 或检索特权信息，而是直接从策略自身蒸馏技能信号。

📒 精读笔记: LLM-MAS Simulation

Optimizing Service Operations via LLM-Powered Multi-Agent Simulation

一句话总结：提出 LLM-MAS 框架，将 LLM 多智能体仿真建模为受控马尔可夫链上的随机优化问题，通过零阶梯度的 on-trajectory learning 算法在单次仿真中同时估计梯度和更新设计参数，优化服务系统运营。

1. 研究动机与问题定义

核心问题

服务系统（供应链、竞赛设计、数字市场等）的性能取决于参与者对设计选择的响应，但人类行为建模极其困难： - 分析模型（效用函数等）过度简化，难以捕捉行为偏差 - 实验数据采集成本高（实验室/实地实验） - 人类决策受认知局限影响，偏离完全理性假设

创新思路

用 LLM 作为人类行为的 "硅基代理"（silicon proxy），在多智能体仿真中模拟人类决策。与传统 Agent-Based Modeling 不同，LLM-MAS 不需要手工编写行为规则，而是利用 LLM 预训练中习得的人类行为统计模式。

2. 方法详解

2.1 问题建模：决策依赖不确定性

将系统设计优化建模为决策依赖不确定性（decision-dependent uncertainty）下的随机优化：

$$\min_{\theta \in \Theta} \left\{ f(\theta) \coloneqq \mathbb{E}_{\xi \sim \mu_\theta} [F(\theta; \xi)] \right\}$$

其中： - $\theta \in \Theta \subseteq \mathbb{R}^d$ 为设计参数向量 - $\xi \in \Xi$ 为系统不确定性（智能体行为 + 系统结果） - $\mu_\theta$ 为给定设计 $\theta$ 下 $\xi$ 的稳态分布 - $F(\theta; \xi)$ 为成本函数

关键特点：$\theta$ 嵌入在 prompt 中，改变 token 概率分布，进而影响智能体行为，使得 $\mu_\theta$ 随 $\theta$ 变化。

2.2 受控马尔可夫链建模

将 LLM-MAS 的状态演化建模为受控 Markov Chain：

$$\xi_{n+1} \sim P_\theta(\cdot \mid \xi_n)$$

其中 $P_\theta$ 为给定设计 $\theta$ 下的转移核。系统状态 $\xi$ 通过从 LLM prompt 和 response 中提取紧凑的数值变量构建。

2.3 零阶梯度估计

由于 $\mu_\theta$ 的解析形式不可得，使用零阶方法（Zeroth-Order Optimization）构建梯度估计：

$$\hat{g}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u$$

其中 $u$ 为随机扰动方向，$\delta > 0$ 为扰动步长，$\xi^+, \xi^-$ 分别在 $\theta + \delta u$ 和 $\theta - \delta u$ 下采样。

2.4 On-Trajectory Learning 算法

核心创新——在单次仿真运行中同时完成梯度估计和参数更新，使用双时间尺度（two-timescale）方案：

$$\theta_{n+1} = \Pi_\Theta \left[ \theta_n - \alpha_n \hat{g}_n \right]$$

其中 $\Pi_\Theta$ 为投影算子，$\alpha_n$ 为步长序列。快时间尺度运行仿真生成数据，慢时间尺度更新设计参数。

与标准多轨迹方法（需要多次完整仿真）相比，on-trajectory learning 从整条状态路径学习，大幅减少 LLM 查询次数。

2.5 方差缩减技术

引入两种方差缩减方法：

引导扰动（Guided Perturbation）：利用成本函数 $F$ 的已知结构，将扰动集中在不确定性大的维度：

$$\hat{g}^{\text{GP}}(\theta; \xi) = \frac{F(\theta + \delta u; \xi^+) - F(\theta - \delta u; \xi^-)}{2\delta} u + \nabla_\theta F(\theta; \bar{\xi})$$

残差反馈（Residual Feedback）：在结构未知时，利用历史迭代信息减少方差。

2.6 收敛性分析

通过 Stochastic Approximation 的 Poisson 方程方法证明算法收敛：

定理（渐近收敛）：在适当的步长条件和马尔可夫链混合条件下，on-trajectory learning 算法满足：

$$\theta_n \to \theta^* \quad \text{a.s.}$$

其中 $\theta^*$ 为稳态目标函数 $f(\theta)$ 的驻点。

5. 核心概念

  • Controlled Markov Chain：将 LLM-MAS 的状态演化建模为设计参数控制的马尔可夫链
  • Zeroth-Order Optimization：无需梯度的优化方法，通过函数值估计梯度
  • Stochastic Approximation：随机逼近理论，on-trajectory learning 的收敛性证明基础

  • Decision-Dependent Uncertainty：不确定性分布随决策变量变化的优化问题

6. 优缺点分析

优点

  1. 理论贡献扎实：将 LLM-MAS 形式化为受控马尔可夫链，提供了严格的数学框架
  2. 算法高效：on-trajectory learning 在单次仿真中完成，避免了多轨迹方法的高昂 LLM 推理成本
  3. 收敛保证：提供了渐近收敛的理论证明
  4. 方差缩减：两种技术分别适用于结构已知和未知场景
  5. 实证验证：真实行为数据的竞赛设计案例增强说服力
  6. 可解释性：LLM 推理过程提供了决策逻辑的透明度

缺点

  1. 核心假设脆弱：LLM 行为分布与真实人类的差距未被正面回答
  2. 仅用开源模型：未在 GPT-4/Claude 等更强模型上验证
  3. 应用场景有限：仅测试了供应链和竞赛设计两个场景
  4. 马尔可夫假设：实际人类决策可能具有长期记忆，违反马尔可夫性
  5. 不做微调：假设 LLM "开箱即用" 即可准确模拟人类行为，但不同文化/人群的行为差异如何处理？
  6. 计算成本：虽然比多轨迹方法高效，但 LLM 推理仍然昂贵

  • 前序工作 (Chatlatanagulchai et al., 2025) 仅研究了 253 个 Claude Code 文件，范围有限

本文的动机

Agent 上下文文件作为一种新型软件工件（"READMEs for agents"），在 Agentic Coding 生态中扮演关键角色，但学术界对其缺乏基本的经验性认知。本文旨在通过大规模实证分析填补这一空白。

方法详解

研究设计

本文围绕四个研究问题（RQ）展开：

  • RQ1: Agent 上下文文件的特征（大小、可读性、结构）是什么？
  • RQ2: 开发者维护 Agent 上下文文件的频率如何？
  • RQ3: Agent 上下文文件包含哪些指令？
  • RQ4: 能否自动分类 Agent 上下文文件中的指令？

数据收集

数据来源: AIDev 数据集 (Li et al., 2025b)，筛选 GitHub Stars ≥ 5 的 8,370 个仓库

文件检索: 通过 GitHub API 扫描仓库根目录，按官方命名规范检索： - CLAUDE.md → Claude Code（922 个） - AGENTS.md → OpenAI Codex（694 个） - copilot-instructions.md → GitHub Copilot（687 个） - 总计: 2,303 个文件来自 1,925 个仓库

RQ1: 特征分析方法

  • 大小: 正则表达式 \w+ 匹配单词数
  • 可读性: FRE 指标（越高越易读）
  • 结构: 统计 Markdown 标题层级（H1-H5）分布
  • 统计检验: Mann-Whitney U Test + Cliff's Delta 效应量

RQ2: 维护模式分析

  • 提取所有修改 ACF 的 commit 历史
  • 统计 commit 数量、时间间隔、增删行数
  • 总计分析 5,655（Claude Code）+ 2,767（Codex）+ 2,237（Copilot）= 10,659 次 commit

RQ3: 内容分类方法

两阶段人工标注:

  1. 标签创建阶段: 提取 H1/H2 标题 → 3 个 LLM（Claude Opus 4.1、Gemini 2.5 Pro、GPT-5）生成候选标签 → 人工筛选 → 80 个初始标签 → 合并为 16 个核心类别
  2. 标签分配阶段: 2 位标注员独立标注 332 个 Claude Code 文件 → 80.3% 一致率 → 第 3 位标注员调解分歧 → 最终 2,069 个标签分配

RQ4: 自动分类方法

  • 任务: 多标签分类（16 个类别）
  • 模型: GPT-5
  • 输入: 完整 ACF 内容 + 每个类别的描述和示例
  • 评估: Precision / Recall / F1-score（per-category + micro average）

关键公式

公式1: 效应量判断标准

$$ \text{Effect size} = \begin{cases} \text{negligible}, & \text{if } |d| \leq 0.147 \\ \text{small}, & \text{if } 0.147 < |d| \leq 0.33 \\ \text{medium}, & \text{if } 0.33 < |d| \leq 0.474 \\ \text{large}, & \text{if } 0.474 < |d| \leq 1 \end{cases} $$

含义: 用 Cliff's delta $d$ 量化两组样本之间差异的实际显著性，补充 Mann-Whitney U Test 的统计显著性判断

符号说明: - $d$: Cliff's delta 值，范围 $[-1, 1]$ - $|d|$: delta 的绝对值

公式2: Flesch Reading Ease

$$ FRE = 206.835 - 1.015 \times \frac{\text{total words}}{\text{total sentences}} - 84.6 \times \frac{\text{total syllables}}{\text{total words}} $$

含义: 衡量文本可读性，分数越高越容易阅读（0-100 范围）

符号说明: - $FRE$: Flesch Reading Ease 分数 - 低于 30 为 "Very Difficult"（大学毕业生水平） - 30-50 为 "Difficult"（大学水平）

核心发现汇总

RQ1 — 特征: - ACF 普遍长且难读，Claude Code 最难读（FRE 中位数 16.6） - 一致的浅层层级结构：单一 H1 + H2/H3 组织

批判性思考

优点

  1. 规模全面: 2,303 个文件、1,925 个仓库、3 种工具，是该领域迄今最大规模的实证研究
  2. 实践价值高: 16 类指令 taxonomy 直接可用于指导 ACF 编写和工具设计
  3. 方法严谨: 多标注员独立标注 + 调解机制，Mann-Whitney U + Cliff's delta 双重统计检验
  4. 洞察深刻: 揭示了 "功能性 vs 非功能性" 指令的显著失衡，对安全和性能有重要警示意义
  5. 可复现: 提供完整 replication package

局限性

  1. 仅分析根目录文件: 可能遗漏子目录中的 ACF（如 .github/copilot-instructions.md）
  2. 二值分类局限: 仅标记类别是否出现，未衡量指令的深度和质量
  3. 仅限开源项目: 企业内部的 ACF 实践可能有显著不同
  4. 人工标注仅覆盖 Claude Code: 332 个文件的标注结果用于推广到全部 2,303 个文件可能存在偏差

潜在改进方向

  1. 纵向追踪研究: 分析 ACF 与代码变更的 co-evolution 关系
  2. 因果分析: 研究 ACF 内容质量对 Agent 生成代码质量的影响
  3. 模板设计: 基于 16 类 taxonomy 设计标准化 ACF 模板
  4. 非功能性需求检测: 开发 CI 集成工具自动检测 ACF 中缺失的 Security/Performance 指令
