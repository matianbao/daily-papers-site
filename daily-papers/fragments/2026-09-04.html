On-Policy Distillation Survey

📋 基本信息

  • 作者: Mingyang Song, Mao Zheng
  • 机构: Tencent
  • 链接: arXiv | PDF

🎯 研究动机与问题

知识蒸馏是将前沿大模型的推理能力迁移到可部署小模型的主要方法。但当前主流范式是 off-policy 的：

  1. 学生模型在静态的教师生成数据上训练
  2. 从未见过自己生成的错误 → exposure bias
  3. 训练-测试不匹配导致推理时错误累积

On-Policy Distillation (OPD) 让学生模型生成自己的 trajectory 并获取教师反馈，本质上是 交互式模仿学习。

本综述是 首个 OPD 的系统性综述。

🔧 方法详解

统一 f-divergence 框架

将所有 OPD 方法统一到 $f$-divergence 框架下：

$$ D_f(p \| q) = \mathbb{E}_{x \sim q}\left[f\left(\frac{p(x)}{q(x)}\right)\right] $$

不同方法对应不同的 $f$ 函数选择： - KL divergence ($f(t) = t\log t$): GKD - Reverse KL ($f(t) = -\log t$): DistiLLM - JSD: MiniLLM

三维分类体系

沿三个正交维度组织：

维度 类别
Feedback Signal Logit-based / Outcome-based / Self-play
Teacher Access White-box / Black-box / Teacher-free
Loss Granularity Token-level / Sequence-level / Hybrid

代表方法分析

方法 Feedback Teacher Granularity
GKD Logit White-box Token
DistiLLM Logit White-box Token
MiniLLM Logit White-box Sequence
DKL Logit White-box Hybrid
DPO Outcome Black-box Sequence
GRPO Outcome Teacher-free Sequence

与 RL 的关系

OPD 与 REINFORCE, PPO, GRPO 等 RL 方法的联系： - On-policy 采样 = RL 中的环境交互 - 教师反馈 = reward signal - Exposure bias = distribution shift

📊 关键对比

综述覆盖了 SFT, DPO, GRPO, REINFORCE 等方法的系统对比。

💡 核心贡献

  1. 首个 OPD 综述：填补了 on-policy distillation 领域的系统性梳理空白
  2. f-divergence 统一框架：用数学工具统一了不同方法的本质区别
  3. 三维分类体系：feedback/teacher access/granularity 提供清晰的方法定位

🤔 局限性与思考

  1. 贡献主要在整理而非发现：survey 在 2026 年不稀缺，关键看能否提供 insight
  2. 实验验证缺乏：作为 survey 没有自己的实验对比
  3. 开放问题有价值：蒸馏 scaling law、不确定性感知反馈、agent-level 蒸馏是值得关注的方向

📚 相关工作

  • GKD, DistiLLM, MiniLLM, DKL: 代表方法
  • SFT, DPO, GRPO, REINFORCE: RL/训练方法
  • KL divergence: 核心数学工具
  • 核心方法: On-Policy-Distillation（OPD）用学生自己 rollout + 教师 token 级 dense 监督。本文把数据推到极限：只用 One-Shot 单条 query 训练，发现能持续改进数百步，跨任务/模型族恢复出全量数据 OPD 大部分收益，并提出 MOPD 变体。
  • 对比方法/Baselines: 对比全量数据 OPD、RLVR、one-shot RLVR（KK 类设置），backbone 含 DeepSeek 系。
  • 借鉴意义: 如果单样本蒸馏成立，意味着「数据规模」在 on-policy 蒸馏里远没想象中重要，对你做小模型对齐/降本的场景是直接可用的省钱结论。
  • 锐评: HF 40 赞不是没道理——「一条样本训几百步还涨」这种反直觉结论天然吸睛。但要警惕：单样本能 work 往往是因为 base model 里知识已经在了，OPD 只是在「唤醒」而非「学习」，泛化边界（摘要说 across domains，但一条 query 的分布覆盖到底多广？）需要盯着看正文的任务集。真结论 or 精心挑的 query，读了才知道。👀

On-Policy Distillation Survey

📋 基本信息

  • 作者: Mingyang Song, Mao Zheng
  • 机构: Tencent
  • 链接: arXiv | PDF

🎯 研究动机与问题

知识蒸馏是将前沿大模型的推理能力迁移到可部署小模型的主要方法。但当前主流范式是 off-policy 的：

  1. 学生模型在静态的教师生成数据上训练
  2. 从未见过自己生成的错误 → exposure bias
  3. 训练-测试不匹配导致推理时错误累积

On-Policy Distillation (OPD) 让学生模型生成自己的 trajectory 并获取教师反馈，本质上是 交互式模仿学习。

本综述是 首个 OPD 的系统性综述。

🔧 方法详解

统一 f-divergence 框架

将所有 OPD 方法统一到 $f$-divergence 框架下：

$$ D_f(p \| q) = \mathbb{E}_{x \sim q}\left[f\left(\frac{p(x)}{q(x)}\right)\right] $$

不同方法对应不同的 $f$ 函数选择： - KL divergence ($f(t) = t\log t$): GKD - Reverse KL ($f(t) = -\log t$): DistiLLM - JSD: MiniLLM

三维分类体系

沿三个正交维度组织：

维度 类别
Feedback Signal Logit-based / Outcome-based / Self-play
Teacher Access White-box / Black-box / Teacher-free
Loss Granularity Token-level / Sequence-level / Hybrid

代表方法分析

方法 Feedback Teacher Granularity
GKD Logit White-box Token
DistiLLM Logit White-box Token
MiniLLM Logit White-box Sequence
DKL Logit White-box Hybrid
DPO Outcome Black-box Sequence
GRPO Outcome Teacher-free Sequence

与 RL 的关系

OPD 与 REINFORCE, PPO, GRPO 等 RL 方法的联系： - On-policy 采样 = RL 中的环境交互 - 教师反馈 = reward signal - Exposure bias = distribution shift

📊 关键对比

综述覆盖了 SFT, DPO, GRPO, REINFORCE 等方法的系统对比。

💡 核心贡献

  1. 首个 OPD 综述：填补了 on-policy distillation 领域的系统性梳理空白
  2. f-divergence 统一框架：用数学工具统一了不同方法的本质区别
  3. 三维分类体系：feedback/teacher access/granularity 提供清晰的方法定位

🤔 局限性与思考

  1. 贡献主要在整理而非发现：survey 在 2026 年不稀缺，关键看能否提供 insight
  2. 实验验证缺乏：作为 survey 没有自己的实验对比
  3. 开放问题有价值：蒸馏 scaling law、不确定性感知反馈、agent-level 蒸馏是值得关注的方向

📚 相关工作

  • GKD, DistiLLM, MiniLLM, DKL: 代表方法
  • SFT, DPO, GRPO, REINFORCE: RL/训练方法
  • KL divergence: 核心数学工具
  • 核心方法: On-Policy-Distillation（OPD）用学生自己 rollout + 教师 token 级 dense 监督。本文把数据推到极限：只用 One-Shot 单条 query 训练，发现能持续改进数百步，跨任务/模型族恢复出全量数据 OPD 大部分收益，并提出 MOPD 变体。
  • 对比方法/Baselines: 对比全量数据 OPD、RLVR、one-shot RLVR（KK 类设置），backbone 含 DeepSeek 系。
  • 借鉴意义: 如果单样本蒸馏成立，意味着「数据规模」在 on-policy 蒸馏里远没想象中重要，对你做小模型对齐/降本的场景是直接可用的省钱结论。
  • 锐评: HF 40 赞不是没道理——「一条样本训几百步还涨」这种反直觉结论天然吸睛。但要警惕：单样本能 work 往往是因为 base model 里知识已经在了，OPD 只是在「唤醒」而非「学习」，泛化边界（摘要说 across domains，但一条 query 的分布覆盖到底多广？）需要盯着看正文的任务集。真结论 or 精心挑的 query，读了才知道。👀
