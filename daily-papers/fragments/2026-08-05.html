1. Orchard: An Open-Source Agentic Modeling Framework

  • 作者: Baolin Peng†\dagger1 🖂
  • 机构: 1Microsoft Research  2Columbia University  3UIUC, {baolinpeng,jfgao}@microsoft.com
  • 链接: arXiv | PDF
  • 来源: 🔥 HF Trending，⬆️ 21
  • 核心方法: Orchard 是 MSR 出的开源 agentic modeling 框架，核心洞察是把 环境层 从 agent harness、model serving、training orchestration 里彻底解耦成一个瘦的、独立的 service boundary，任意 trainer × agent 设计 × 任务域都能拼同一套环境服务。配合低成本镜像复用，支持 RL 和 SFT 跨 SWE、GUI、Web 等多域训练。
  • 对比方法/Baselines: 对标 OpenHands、WebVoyager 这类偏应用的 harness，以及依赖闭源 codebase 的高性能系统。
  • 借鉴意义: 如果你想真正自己训 agent 而不是调 API，环境层的工程债是最大的坑。Orchard 把这块开源出来，比又一篇 'prompt engineering 让 agent 变强' 有价值得多。
  • 锐评: MSR + Columbia + UIUC 的组合，做的是别人不愿意做的脏活累活——基建。'thin standalone service boundary' 这个设计原则说得很对：现在开源 agent 框架最大问题就是训练/推理/环境三者纠缠。就是希望别只是又一个 star 冲榜后无人维护的 repo。想训 agent 的直接抄基建。🔥

2. LongHorizon-Harness: Advancing Long-Horizon Agents for Real-World Tasks

  • 作者: Ziyu Ma, Hailang Huang, Shun Zou, Yong Wang, Shidong Yang, Yiming Hu, Fei Wei, Xiangxiang Chu
  • 机构: [ ]DreamX Team, Alibaba Group\affiliationlist\affiliationformat
  • 链接: arXiv | PDF
  • 来源: 🔥 HF Trending，⬆️ 135
  • 核心方法: LongHorizon-Harness 直指长程 agent 的核心病：任务执行、任务状态、完成度评估全塞在一个不断膨胀的 context 里，导致状态难追踪、错误的 self-assessment 会传染到后续决策。方案是把这三者从 context 里剥离出来做显式管理，覆盖 Terminal-Bench、WeaveBench 等长程 CLI/GUI 任务。
  • 对比方法/Baselines: 对比 OpenClaw 等 harness，用 GPT-5 做 backbone，指标看 PassRate。
  • 借鉴意义: 'incorrect self-assessment 传染' 是所有做长程 agent 的人都踩过的坑——用户做的 CTR/推荐 pipeline 如果上 agent 编排，这个状态管理教训直接适用。
  • 锐评: 阿里 DreamX Team，135 个 HF 赞是今天最高。问题抓得准：context 膨胀 + 自评污染确实是长程 agent 的死穴。把 state 从 context 里拆出来做显式追踪是对的方向，不是新想法但工程落地有价值。唯一担心是 harness 类论文容易 benchmark 打得漂亮、换个任务就崩。看它对新任务的泛化。👀

3. Agentic Reinforcement Learning with Self-Distilled Reward Shaping

  • 作者: Ranxu Zhang, Guinan Chen, Chenshaodong, Jinghao Lin, Xiaozhou Xu, sunzhe, Yanyong Zhang, Chao Wang
  • 机构: Alibaba Group, Alibaba GroupHangzhouChina, University of Science and Technology of China, University of Science and Technology of ChinaHefeiChina
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: ADRS（Agentic RL with Self-Distilled Reward Shaping）解决 agentic RL 的经典难题：trajectory-level 稀疏 reward 只告诉你成没成功，不告诉你哪一步的中间决策该背锅（credit assignment）。做法是让冻结的 policy snapshot 在 task-matched procedural skill 条件下 rescore 无技能轨迹的固定 token，从而蒸馏出更稠密的监督信号。基于 GRPO/GiGPO，在 WebShop 上验证。
  • 对比方法/Baselines: 对比 GRPO、GiGPO 等 group-based RL，涉及 SDAR、OPSD 等组件。
  • 借鉴意义: 稀疏 reward 下的 credit assignment 是 agent RL 的核心瓶颈，自蒸馏稠密奖励这套思路对做 RL 排序/出价的人有借鉴。
  • 锐评: 阿里 + 中科大。'privileged skill 只在训练期提供稠密监督、推理期不用' 这个设计很干净——用同一个冻结快照 rescore 来造 dense reward，避免了额外训 reward model。方法论优雅，但 WebShop 这个 benchmark 已经被刷烂了，只在它上面验证说服力不够。多来两个环境就是强推。🔥

4. CVPO: Enhancing LLM Reinforcement Learning Reasoning via Value-Variance Adaptation and Dynamic Curriculum Learning

  • 作者: Ziqi Jia1,2,◆\blacklozenge
  • 机构: 2Tsinghua University, 1AI Cloud Group, Baidu, 3University of California, San Diego
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: CVPO（Curriculum-guided Value-Variance Policy Optimization）针对 LLM RL reasoning 的两个病：answer trajectory 反馈精度不足、以及 problem difficulty drift（训练中题目难度漂移）。方案是 value-variance adaptation + 动态课程学习，在 AIME/AMC 上验证。基于 PPO/GRPO/VAPO 谱系。
  • 对比方法/Baselines: 对比 GRPO、VAPO、PPO，用 GAE 做 advantage 估计。
  • 借鉴意义: reasoning RL 的调参经验（尤其难度课程和方差自适应）可迁移到任何用 RL 做序列决策的场景。
  • 锐评: 百度 + 清华 + UCSD。'problem difficulty drift' 这个观察挺实在——RL 训练中容易被简单题带偏。value-variance 自适应 + 课程学习都是成熟组件的组合拳，创新性一般但工程完成度看起来不错。属于 GRPO 家族又一个变体，AIME/AMC 数字好看但这条赛道内卷严重。工程向的可以抄参数。🫠

5. Robust General Utility for Reinforcement Learning

  • 作者: Zixuan Liu\corresponding
  • 机构: Department of Computer Science, Tulane University, New Orleans, LA, 70118, USA
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: Robust General Utility RL 把经典 RL 从优化标量 reward 扩展到优化 policy 诱导的 occupancy measure 的任意 utility functional，并进一步处理 utility 被错误指定（misspecification）的情况。形式化为 minimax 目标 min_θ max_ξ f_ξ(λ_θ)，用 PGDA 求解。

  • 对比方法/Baselines: 对比假设 utility 固定且正确的传统 general utility RL 工作，用 Monte-Carlo 估计。
  • 借鉴意义: 'reward/utility 被错误指定' 是所有 RL 落地的隐痛，robust 视角对做出价/排序的 objective 设计有理论参考价值。
  • 锐评: Tulane 单位，偏理论。承认 utility 会被 misspecify 并做 minimax robust 优化，这个问题设定比大多数 'agentic X' 论文诚实得多。缺点是理论论文通病：实验八成是玩具环境。做算法研究的值得扫一眼 formulation，做工程的可以跳。👀

7. Towards Robust Tool Use in Agents via Experience-Driven Adaptive Guidance

  • 作者: Can Wang1,2
  • 机构: 3Department of Electrical and Electronic Engineering, The Hong Kong Polytechnic University, 2Alibaba Token Hub, 1Shandong Key Laboratory of Digital Service Computing Technology and Systems
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: ExpG（Experience-Driven Adaptive Guidance）主张 agent 的性能瓶颈已从模型能力转向执行过程的鲁棒性，工具是 agent 与外部交互的主接口却少有人保证其跨运行时条件的鲁棒工具调用。方案是经验驱动的自适应引导。基于 MetaTool/BFCL 评测，用 DRAFT 等对比。

8. Formal Verification of Agentic Systems over Operational Data

  • 作者: Alejandro J. Mercado1\corresponding
  • 机构: Imperial College London
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: Formal Verification of Agentic Systems 针对部署前对 agent 系统按业务需求做形式化验证的空白——现有方法只在 agent 接口层约束行为，给不出系统级保证。做法是在部署边界强制 equivariance：每个决策上下文先重命名为 canonical 代表再查询 base agent，选中的调用再映射回原标识符，从而无需对 LLM 做 post-hoc 认证。用 CTL 表达业务规则。

  • 对比方法/Baselines: 对比在 agent 接口层做约束/分析的现有形式化方法。
  • 借鉴意义: 对高合规场景（金融、广告审核）的 agent 部署有价值，形式化保证是监管友好的方向。
  • 锐评: Imperial College。把形式化验证套到 agentic system 上是个稀缺方向——大多数人只会加个 guardrail 就说安全了。'canonical renaming + 边界 equivariance' 绕开对 LLM 本身证明的思路很聪明。担心的是可验证的业务需求类别很窄，一旦 agent 行为超出 CTL 能表达的范围就失效。理论人可看。👀

9. OmniPack: Unified Token Compression for Efficient Omni-modal Large Language Models

  • 作者: Su, Wanshun, Shi, Yang, Liu, Feihu, Yu, Ziwen, Min, Yan, Zhang, Zhuoran, Wang, Qixun, Wang, Haotian, Liu, Shixuan, Zhang, Yuanxing, Wu, Peng, Huo, Chengfu, Ding, Liang

  • 链接: arXiv | PDF
  • 来源: 📰 HF Daily，⬆️ 15
  • 核心方法: OmniPack 做 omni-modal LLM 的统一 token 压缩，解决长且高冗余的视觉+音频 token 序列带来的计算开销。指出现有方法在低 token 预算下退化（pre-LLM 压缩会丢结构信息），提出统一压缩方案。对比 VisionZip/FastV/OmniZip。

10. Failure-Informed Image Self-Augmentation for Multimodal Large Language Model Self-Improvement

  • 作者: Chunyang Jiang1\equalcontrib
  • 机构: Chinese University of Hong Kong, City University of Hong Kong, Hong Kong University of Science and Technology
  • 链接: arXiv | PDF

  • 机构: The Chinese University of Hong Kong

  • 来源: 📄 arXiv 关键词检索

  • 锐评: MIT Critical Data 领衔的大兵团。虽然场景是临床（沾了 negative keyword），但核心发现是通用的多 agent 病理：委员会不是纠错机制，而是错误放大器——用权威替代验证、压制正确异议。'oversight 信号必须来自 transcript 之外' 是狠话也是对的。做 multi-agent 的都该读这个反面教材，别再迷信 'debate 提升准确率'。⚠️
