1. VICT: Verifier-Instrumented Credit Tracing for Long-Horizon LLM Agent Reinforcement Learning

  • 作者: Pengcheng Li, Zhengyang Zhang, Dongxu Zhang, Sui Huang, Shaohua Ma
  • 机构: Affiliation: Jiaxing Nanhu University*Corresponding author. Email: lipc24@mails.tsinghua.edu.cn, Affiliation: , Affiliation: Xi’an Jiaotong University, Affiliation: Tsinghua University
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: 针对长程 LLM Agent 的稀疏终端奖励问题，提出 VICT（Verifier-Instrumented Credit Tracing）。不同于主流从 rollout 侧构造辅助信号来估计动作重要性，VICT 反其道从 verifier 侧下手，用可验证器在轨迹中间插桩，把'哪一步真正推动了任务'的信号显式提取出来。在 WebShop 等长程任务上对比 GRPO、RLOO、SALT、HCAPO。
  • 对比方法/Baselines: GRPO、RLOO、SALT、HCAPO
  • 借鉴意义: 推荐/广告里的延迟转化、多步归因本质就是稀疏奖励下的信用分配问题。verifier 插桩这个思路——用一个能判定中间状态好坏的模块把稀疏信号稠密化——可以直接映射到转化路径建模。
  • 锐评: 终于有人不在 rollout 侧卷了。'把稀疏信号变稠密'的老问题，从 verifier 侧切入是个干净的角度。但要命的问题它绕不开：verifier 本身准不准？如果 verifier 会被 reward hacking，那插的桩就是在放大噪声。摘要里没看到对 verifier 鲁棒性的压力测试，这是我打问号的地方。方向对，得看实验细节。🔥

2. Rubric-to-Code Credit Assignment for Reinforcement Learning

  • 作者: Jin, Rui, Chen, Jikai, Chen, Yihan, Zhou, Hao, Zhu, Demin, Yang, Kaichen, Wang, Dong, Zhuang, Chenyi
  • 机构: 1Inclusion AI, Ant Group  2Zhongnan University
  • 链接: arXiv | PDF
  • 来源: 📰 HF Daily，⬆️ 3
  • 核心方法: RCCA（Rubric-to-Code Credit Assignment）针对交互式 Web 应用生成——每个用户功能需求往往对应局部代码区域（事件处理、状态更新、DOM 片段、CSS 选择器）。它把 rubric 拆解并对齐到具体代码区域，做细粒度的 RL 信用分配，而非把一个总分广播给整条轨迹。在 MiniAppBench、ArtifactsBench 上用 GRPO 训练。
  • 对比方法/Baselines: GRPO、SFT
  • 借鉴意义: '把粗粒度奖励拆到最小可归因单元'是所有强化学习落地的核心痛点。这套 rubric→区域的映射方法论对特征级/坑位级的归因建模有借鉴价值。
  • 锐评: 跟 VICT 是同一天的近亲，都在啃 credit assignment。RCCA 的做法更接地气——rubric 本来就是人写的验收标准，拆到代码区域顺理成章。质疑点：rubric 到代码区域的映射谁来做？如果靠 LLM 自己对齐，那这层映射的误差会不会比它想解决的信用分配误差还大？闭环里套了个可能更脏的环节。👀

3. HARTS: Efficient Agentic Reinforcement Learning for Hybrid-Attention Models over Arbitrary Rollout Trees

  • 作者: Boyuan Meng, Peihua Bao, Hong Liu, Xiaowei Zhu, Chao Wang, Gen Li, Zhenxuan Pan
  • 机构: Affiliation: 
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: HARTS（Hybrid-Attention RL over Tree Structures）解决 agentic RL 的一个纯工程痛点：rollout 树有大量共享历史前缀，独立训练每条 root-to-leaf 轨迹会重复计算这些前缀。HARTS 提供了兼容激活重算的稠密可微 hybrid-attention 执行，面向 MoE、MLA、KDA 等架构。

  • 对比方法/Baselines: 面向 full-attention 模型的现有 RL 系统
  • 借鉴意义: agentic RL 训练成本是规模化的最大障碍之一。共享前缀不重算这个优化，对任何要跑大规模 rollout 的团队都是真金白银的省钱。
  • 锐评: 标题一堆缩写吓人，本质是'树形 rollout 别重复算共享前缀'——一句话能说清的工程优化。这不丢人，工程优化就该老老实实做。但它的价值完全取决于共享前缀在真实 rollout 里占比多大，如果分支很早就发散，省的那点算力就是自欺欺人。得看它给的加速比是在什么树形态下测的。⚠️

4. ReToolSQL: Agentic Reinforcement Learning for Robust Text-to-SQL

  • 作者: Pratik Kakkar, Chandra Dhir*, Ravi Shankar, Pareekshit Reddy Gaddam, Anup Shirgaonkar
  • 机构: Affiliation: 
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: ReToolSQL 把 text-to-SQL 从单轮任务改造成多轮 agentic 任务：模型可以通过执行反馈迭代式地修复 SQL 错误，而非一锤子买卖。基于 GRPO/DAPO 做 RLVR（可验证奖励强化学习），在 BIRD 上用 EX 指标评测。

  • 对比方法/Baselines: SFT、RFT、单轮 RL 方法
  • 借鉴意义: '执行反馈 + 多轮修正'是让小模型追平大模型的常见套路，对任何有明确验证信号（SQL 能否执行/结果对不对）的结构化生成任务都通用。
  • 锐评: text-to-SQL + RLVR + 多轮，三个词都是当红炸子鸡，凑一起发论文属于稳妥操作。执行反馈让小模型追平大模型的故事讲了一年了，ReToolSQL 没跳出这个框。真正想看的是：多轮修正到底带来多少增益 vs 单纯多采样几次？如果消融里 self-consistency 就能吃掉大半提升，那'agentic'这个包装就有点虚。🫠

  • 机构: Affiliation: Department of Energy Science and Engineering, Affiliation: , Affiliation: minghuix@stanford.edu; ziwang3@stanford.edu, Affiliation: Stanford University

6. JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution

  • 作者: Zhang, Guibin, Lu, Leo, Xie, Fangzhou, Zhu, Kang, Wang, Junhao, Xie, Zhifei, Yu, Zhaochen, Liu, Zihang, Sun, Zhongxiang, Li, Qiankun, Liao, Yue, Chang, Heng, Hu, Xiaobin, Ren, Qibing, Zhou, Wangchunshu, Yan, Shuicheng
  • 机构: Scaling Harness Intelligence via Just-in-Time Harness Evolution
  • 链接: arXiv | PDF
  • 来源: 🔥 HF Trending，⬆️ 111
  • 核心方法: JIT-Agent 的核心论点很尖锐：agent 能力不由模型单独决定，harness（记忆管理、规划策略、动作协议、工具/技能编排）的贡献可以盖过底座模型。但 harness 设计至今是手工、任务特定、无法规模化的。JIT-Agent 提出 just-in-time 的 harness 演化机制，让 harness 自动进化。在 DeepSearchQA、DeepPlanning、AgentIF 上评测。
  • 对比方法/Baselines: ReAct、AOT 等固定 harness
  • 借鉴意义: 这个论点对做 agent 应用的团队是当头棒喝——你花大力气换模型，可能不如好好调 harness。对推荐 agent、广告投放 agent 的架构设计有方向性指导。
  • 锐评: 'harness 才是天花板，不是模型'这个论断我举双手赞成，也是今天最值得转发的一句话。问题在于'just-in-time 演化'落地起来极容易变成又一个玄学 AutoML——搜索空间怎么定义、演化信号从哪来、会不会过拟合到 benchmark，这三个坑一个没填好就是花架子。方向 100 分，能不能兑现看工程细节。👀

7. SkillOpt: Executive Strategy for Self-Evolving Agent Skills

  • 作者: Yang, Yifan, Gong, Ziyang, Huang, Weiquan, Yang, Qihao, Zhou, Ziwei, Huang, Zisu, Li, Yan, Gao, Xuemei, Dai, Qi, Liu, Bei, Qiu, Kai, Yang, Yuqing, Chen, Dongdong, Yang, Xue, Luo, Chong
  • 机构: Fudan University, Microsoft, Shanghai Jiao Tong University, Tongji University
  • 链接: arXiv | PDF

  • 来源: 🔥 HF Trending，⬆️ 264

  • 核心方法: SkillOpt 主张：agent 的 skill 应该像深度学习优化器训练权重那样被'训练'——把 skill 当成冻结 agent 的外部状态，用同样的可复现纪律去优化。批评了当前 skill 要么手写、要么一次性生成、要么松散自我修订，都不像真正的优化器。对比 GEPA、TextGrad、EvoSkill，在 SpreadsheetBench、LiveMath、SearchQA 上评测。

  • 对比方法/Baselines: GEPA、TextGrad、EvoSkill
  • 借鉴意义: 'skill = 外部可训练状态'这个抽象很干净，把 prompt/skill 优化纳入了和权重优化同构的框架，对系统化改进 agent 有理论价值。
  • 锐评: 跟 JIT-Agent 打对台，都盯上了'agent 的外部状态该怎么系统化优化'。SkillOpt 的类比更漂亮——把 skill 当权重训。但类比漂亮不等于有效：权重优化有梯度，skill 空间是离散的自然语言，所谓'同样的纪律'能复现到什么程度是最大悬念。如果本质还是黑盒 LLM 反思，那'像优化器一样'就只是修辞。👀

11. When Linguistic and Internal Confidence Diverge in Large Language Models

  • 作者: Hefan Zhang, Bingquan Zhang, Ming Cheng, Saeed Hassanpour, Weicheng Ma, Soroush Vosoughi
  • 机构: Affiliation: Oakland University, Affiliation: Dartmouth College, Affiliation: 
  • 链接: arXiv | PDF

  • 来源: 📄 arXiv 关键词检索

  • 核心方法: 研究 LLM 的'语言置信'（模型嘴上说的自信程度）是否真的追踪其'内部置信'。跨 8 个分类任务、2 个生成任务、3 个模型家族的 30 个模型，分类任务上对比语言置信与 logits 置信（关联性、量级一致性、校准 ECE），生成任务上对比语义熵 SE。

  • 对比方法/Baselines: logits-based confidence、semantic entropy
  • 借鉴意义: 在推荐/广告里如果用 LLM 做打分或判断，'它说 90% 确定'到底可不可信直接关系到能否用它的置信度做阈值决策。这篇给了系统性的答案。
  • 锐评: 一个特别实在的问题：模型说'我很确定'的时候它真的确定吗？答案不出意外是'经常不确定'。这种大规模跨模型的实证研究没什么花哨方法，但价值恰恰在覆盖面——30 个模型的结论比单模型 anecdote 靠谱得多。想拿 LLM 的口头置信做决策阈值的人，读完可能会冷汗直流。👀

  • 机构: Affiliation: Korea Advanced Institute of Science and Technology (KAIST), {dpenguin, jhyuk, kw.ko, hskim98, changick}@kaist.ac.kr, Affiliation: , Wonjun Lee
  • 链接: arXiv | PDF
  • 来源: 📄 arXiv 关键词检索
  • 核心方法: AIM（Anchor Identity features, then Match）研究多模态 LLM 的身份遗忘（unlearning）——当某人要求删除其隐私数据时，现有方法通常假设删除时能拿到 retain 图像或 ground-truth 答案，这不现实。AIM 在没有 retain 图像的情况下做身份遗忘，先锚定身份特征再匹配。在 MLLMU 上评测。
